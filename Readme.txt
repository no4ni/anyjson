anyjson
=======
Инструмент, которым внешний LLM (DeepSeek, GPT и т.п.) пользуется через JSON-команды.
Пользователь вводит JSON в консоль anyjson - команды выполняются. Обратной связи
"LLM внутри anyjson" нет, LLM снаружи.
---
Кто читает этот файл
--------------------
Ты — внешний LLM, помощник разработки anyjson. Ты не агент и не пользователь (оператор).
Ты не выполняешь команды и не работаешь с ФС напрямую. Ты формулируешь патчи и команды текстом,
оператор выполняет их сам. Слово "пользователь" в этом файле всегда означает оператора.
**Readme - твоя ответственность.** Следи, чтобы он оставался актуальным и не превышал 100 КБ (102400 Б).
Когда добавляешь команду, меняешь поведение, узнаёшь новую граблю - сразу давай оператору команду
обновить Readme через заменить_текст / переписать. Проверяй размер через список_файлов (отдаёт байты).
**Не выноси разделы в отдельные файлы (docs/, troubleshooting.txt и т.п.) ради обхода лимита.**
Лимит — на суммарный объём документации. Если не влезает — сокращай содержание: вырезай устаревшее,
дубли, гайды "как пользоваться" и списки параметров (они есть в докстрингах/справке).
Оставляй только то, без чего невозможно чинить anyjson в следующей сессии: структура и пути,
восстановление при падении старта (PowerShell, here-string, бэкап, py_compile), грабли, контракты, безопасность.

Доступ - косвенный, через оператора. Называй ПОЛНЫЙ путь (например, E:\Jericho\Private\anyjson\_core\_ps.py).
Запрашивай файлы целиком (через прочитать_полностью / читать_по_кб), а для гигантских файлов —
конкретную функцию через прочитать_функцию.

Патчи: правила работы
1. Многострочный текст в PS-консоль - только через here-string (\$insert = @' ... '@), не через @(...) -join.
2. Не выдумывай пути. Неизвестные файлы ищи через найти_файл / найти_всё / список_файлов.
   найти_файл после выбранного результата печатает секцию "📋 Другие совпадения (пути):" (окно соседних путей, параметр других_путей=30).
3. Патч любого *.py - только с бэкапом: {"создать_бэкап": {"путь": "E:/путь/к/файлу.py"}}.
   Старые *.bak_* чисти штатно через удалить_старые_бэкапы.
4. Якоря для Replace - уникальные (проверяй Count вхождений).
5. Все патчи - одной |||-цепочкой в ОДНОМ блоке ```text (НЕ ```json — браузер ломает длинные строки в json-блоке).
   Оператор выполняет ТОЛЬКО первый блок в ответе, остальные теряются молча.
   ВАЖНО: ||| ставится вплотную к } предыдущей команды на ТОЙ ЖЕ строке (никаких переводов строки перед |||).
6. Лимит одного блока ```text в веб-чате: ~90-100 строк (и без сверхдлинных строк без переносов, иначе браузер рвёт рамку кода и выкидывает хвост наружу).
   Крупные файлы пиши порциями по 50-80 строк: сначала переписать, затем добавить (оставляя пустую строку после открывающего маркера).
   Нет подтверждения («✅ Заменено») = патч НЕ применён. Проверяй факт через найти_файл, если оператор не ответил.
7. Если anyjson не запускается (валидатор, SyntaxError, guard) — JSON-команды бесполезны.
   Чини через PowerShell here-string: ReadAllBytes → GetString → Replace → py -m py_compile → WriteAllBytes.
8. Вложенные heredoc-маркеры (тройные угловые скобки) поддерживаются (счётчик глубины int in_heredoc в anyjson.py, cmd_parser.py, _utils.py).
   Одиночный маркер без пары собирай через chr(60)*3 / chr(62)*3.
9. Отступы в якорях - точные (4 пробела). Копируй из вывода осмотреть / найти_функцию. Перед записью — предпросмотр: true.

Формат ввода
------------
- Одна команда: {"имя_команды": {"параметр": "значение"}}
- Последовательно: ||| вплотную к } предыдущей команды (после ||| можно перенос строки). При >=2 командах печатается прогресс-метка X/Y · имя_команды.
- Одновременно: {"параллельно": [{"эхо": "a"}, {"эхо": "b"}]} (не для зависимых шагов).
- Короткая запись: голая строка без словаря уходит в "путь" для файловых команд (_PATH_COMMANDS) и в "запрос" для остальных.
- Многострочный JSON: REPL копит ввод до баланса { и [ вне кавычек. Пустая строка — принудительный запуск.
- Inline-heredoc: тройные угловые скобки внутри любого строкового параметра JSON без экранирования (обрезает по одному \n с краёв; не оставляй 3 пустые строки подряд).
- Автопочин скобок: при нехватке } или ] в конце anyjson дописывает их с предупреждением ⚠️.
- Автотрим лишней } в конце (Extra data): срезает хвост, проверяя через _extract_actions.
- Shell-питон: ввод `python x.py args` блокируется с готовым JSON-шаблоном для "питон". Команда «запустить»/«запуск» для .py делегирует в «питон».

Правки файлов (для LLM)
-----------------------
- переписать (перезаписать_файл, записать_файл, переписать_файл): путь, содержание/содержимое, подтвердить_потерю (true, если новый текст короче). Создаёт бэкап .bak_YYYYMMDD_HHMMSS перед записью.
- добавить: дописать в конец (путь, содержание, склеить — безопасная склейка строк).
- заменить_текст: путь, найти, заменить, все, регистр, регулярка, предпросмотр, показать_близкое, без_проверки, слабый_отступ, без_отступов.
  • слабый_отступ (false для .py, true для остальных): ведущие пробелы строк якоря -> [ \t]* (не пересекает строки). Строка без ведущих пробелов не флексится — бери реальный отступ из "ближайшие совпадения".
  • без_отступов: сравнение по lstrip() с сохранением оригинальных отступов (требует равного числа строк).
  • гибкий поиск (всегда вкл.): NBSP↔пробел, тире↔дефис, «»↔"", CRLF↔LF.
  • для *.py перед записью идёт проверка синтаксиса (сломанный код не пишется; обход — без_проверки: true).
- заменить_функцию: имя, путь, содержание/содержимое/код (бэкап + AST-проверка).
- найти_функцию / прочитать_функцию / проверить_синтаксис / осмотреть (через side/inspect.ps1).
- создать_бэкап / удалить_старые_бэкапы (чистит *.bak* старше N дней и profiles/*/memory/tmp*.py).
- дедуплицировать_строки (убрать_дубли_строк, dedupe_lines).
- not_a_file_msg (в _core/_utils.py): единый отказ для file-only команд на папках (пути нормализуются на прямые слэши).

Hot-reload
----------
Правки подхватываются на лету МЕЖДУ пакетами команд (не внутри одной |||-цепочки):
- ✅ reload: _actions/*.py, _core/_utils.py, _core/_color.py, _core/_executor.py, _core/_ps.py, _core/_py_guard.py (без warn).
- ⚠️ нужен перезапуск: _core/_config.py, _storage.py, _tor.py, _safe_subprocess.py, _web.py, _server.py.
- ❌ не отслеживается: anyjson.py.
Правило: в anyjson.py и _core/*.py делай `import X` + `X.foo()`, а не `from X import foo` (иначе reload не обновит локальную ссылку).

Фильтры безопасности
--------------------
1. Страж subprocess (_core/_safe_subprocess.py): разрешает .py только внутри BASE_DIR (кроме контекста allow_external_py() в команде "питон"). Блокирует subprocess.*, os.system, os.popen, shell=True с внешним python.
2. Запрет записи (переписать/добавить): C:\Windows, C:\Program Files, C:\Program Files (x86), C:\ProgramData, чужой профиль (profiles/<ДругойАгент>/...).
3. Ограничения {"питон"}:
   - Быстрый regex-блок: os.system, subprocess, eval, exec, socket, requests, shutil.rmtree.
   - Audit hook (_core/_py_guard.py): блокирует запись/удаление/переименование/rmtree в системных папках (os._exit(3)), os.system/os.exec, shutil.rmtree (везде), subprocess.Popen (кроме ffmpeg/ffprobe из доверенных путей без shell-метасимволов; soft PermissionError). ROCm-пробы подавляются молча.
   - Guard не изолирует нативные вызовы (ctypes, win32com). Режим в_файл пишет вывод в консоль и файл, а в контекст отдаёт сводку.
4. leak_guard и mask_secrets: leak_guard блокирует отправку секретов (пароли, токены, ключи, hex 40+) во внешние сервисы (Moltbook, UNaIVERSE). tools_leak_guard.mask_secrets() маскирует email, токены и base64url (≥40 символов) на * в любом выводе.

ВЕБ-ИНТЕРФЕЙС (Web Server)
==========================
- Запуск: `py E:\Jericho\Private\anyjson\web_server.py` → http://127.0.0.1:8081 (слушает только localhost).
- Архитектура: web_server.py → _core/_server.py (HTTP + SSE + цикл модель↔демон) + _core/web_ui.html (читается при каждом запросе, правки видны по F5; изменения _server.py требуют перезапуска сервера).
- Демон: `agent.py --daemon` (ANYJSON_DAEMON=1 / ANYJSON_WEB=1, виртуальный буфер в памяти вместо pyperclip). Общается построчным JSON по stdin/stdout; эфемерные строки `{"progress": "..."}` идут в SSE как `type: "progress"`. Hot-reload `_actions/*.py` работает между командами.
- Tools API (нативный llama.cpp): _build_tools() отдаёт поиск_команд, выполнить_команду, справка (fallback-парсинг текста _detect_json удалён; в описаниях tools не упоминать имя обвязки).
- прочитать_полностью в веб-режиме (веб=true): текст <8 КБ целиком, >=8 КБ делегируется в читать_по_кб (блок 4 КБ), картинки ресайзятся до 0.5 МПикс в base64 Data URL, прочее уходит в команду «сенсор».
- Сжатие контекста (_compress_history_inplace / H._compress_history_now): запускается после ответа ассистента (или принудительно при > thrconsize_force = 33% * 1.36 от n_ctx). При ошибке убивает дочерний процесс T5.
- UI (web_ui.html): инкрементальный рендер чанков, счётчик токенов 5К/10К/32К (текущие/порог/окно), прикрепление до 4 картинок (<=12 МБ, даунскейл до 0.5 МПикс), редактирование сообщений ✎, сброс сессии 🔄, /favicon.ico → 204.

- Файловые операции: в `_actions/tools_files.py` добавлена `copy_file_with_progress` (побайтовый `tqdm` для файлов ≥ 5 МБ), подключена в `переместить` (при междисковом переносе) и `копировать`; в `поиск_в_файлах` добавлен алиас `текст`.
- Мульти-поиск (`веб_поиск`): в `side/web_search.py` и `_actions/web_search.py` встроен авто-фолбэк по 7 движкам (`bing` с развёртыванием `u=a1...`, `ddg_html`, `ddg_lite`, `searxng`, `anysearch`, `exa` MCP, `ddgs`), выбор движка параметром `движок` и поддержка Ollama Web Search API (`ollama` в `api_keys.json` / `OLLAMA_API_KEY`).
- Настройка (`настроить`): в `_actions/settings.py` добавлен режим мастера `{"настроить": {"мастер": true}}`, запрашивающий только недостающие пути и ключи из `*.example.json`.
