anyjson
=======
Инструмент, которым внешний LLM (DeepSeek, GPT и т.п.) пользуется через JSON-команды.
Пользователь вводит JSON в консоль anyjson - команды выполняются. Обратной связи
"LLM внутри anyjson" нет, LLM снаружи.
---
Кто читает этот файл
--------------------
Ты — внешний LLM, помощник разработки anyjson. Ты не агент и не пользователь (оператор). 
Ты не выполняешь команды и не работаешь с ФС напрямую. Ты формулируешь патчи и команды текстом, 
оператор выполняет их сам.
Слово "пользователь" в этом файле всегда означает оператора,
а не тебя.
Прямого доступа к файловой системе у тебя нет: ты не выполняешь
команды, не читаешь и не пишешь файлы сам. Ты видишь только
то, что оператор вставил в чат, и влияешь только на то, что
оператор запустил.
**Readme - твоя ответственность.** Следи, чтобы он оставался
актуальным и не превышал 100 КБ. Когда добавляешь команду, меняешь
поведение, узнаёшь новую граблю - сразу давай оператору команду
обновить Readme. Не спрашивай "дописать?" - просто отдавай команду
через заменить_текст / переписать. Следи за размером через
список_файлов (он репортит БАЙТЫ, не КиБ); если > 102400 Б
(100 КиБ), вырезай устаревшее (или через
подсказать_сокращения, но помни: для технической документации
T5 врёт, ручная редактура надёжнее).

**Не выноси разделы в отдельные файлы (docs/, troubleshooting.txt
и т.п.) ради обхода лимита.** Лимит — на суммарный объём
документации, а не на один файл. Если не влезает — сокращай
содержание: вырезай устаревшее, дубли, пересказ того, что и так
есть в коде/справке. Разнос по файлам — тот же обход, только
в профиль.
Что в Readme обязательно, а что нет. Readme - инструкция по ремонту
для тебя в следующей сессии, не справочник для оператора.
Обязательно: структура и пути; как чинить, когда anyjson не стартует
(PowerShell, here-string, бэкап, py_compile); тактические уроки и
грабли ("не перебирай якоря через питон", "json.loads первичен");
контракты между модулями; фильтры безопасности.
Необязательно (сжимай первым): гайды "как пользоваться командой";
детали реализации вне ремонта (блюр IDW, флаги TFLite); примеры и
списки параметров - они в докстрингах/справке; история "раньше было
так" - только если влияет на текущий код.
Проверка: удалив абзац, не можешь представить, как без него чинить
anyjson - оставляй.
Доступ - косвенный, через оператора. Ты даёшь команды и патчи,
оператор их выполняет. Ты называешь путь - оператор отдаёт
содержимое.
Поэтому: чтобы получить файл, назови ПОЛНЫЙ путь. Не "открой
_ps.py", а:
    E:\Jericho\Private\anyjson\_core\_ps.py
Оператор сам решит, как отдать содержимое: скопирует из
редактора, прогонит через {"читать_по_кб": {"путь": "..."}}
или {"прочитать_полностью": {"путь": "..."}}.
Патчи - тоже с полного пути. "Патчим _ps.py" - плохо.
"Патчим E:\Jericho\Private\anyjson\_core\_ps.py" - хорошо.
Запрашивай файлы целиком, не фрагментами. "Покажи строки 250-330"
теряет контекст (импорты, соседние функции, отступы), и через
итерацию всё равно придётся просить ещё кусок. Один полный файл
читается быстрее, чем пять точечных запросов. Исключение -
гигантский файл (тысячи строк): тогда конкретную функцию
по имени через прочитать_функцию.
---
Изображения (ты их видишь)
Чтобы увидеть картинку, попроси оператора выполнить
{"посмотреть_картинку": {"путь": "..."}}. Результат оператор
вставит в чат. Используй для визуальной оценки: апскейл, кроп,
цветокор, композит, рендер, качество результата.

Патчи: правила работы
Правило первое. Многострочный текст в PS-консоль - через
here-string:
  $insert = @'
  строка
  строка
  '@
Не через @(...) -join: при вставке из буфера в консоль массив
может схлопнуться в пустую строку, Replace() молча удалит
якорь, файл останется без вставки.
Правило второе. Не выдумывай пути. Если полного пути нет -
скажи оператору, какой файл нужен, попроси найти
(найти_файл / найти_всё / список_файлов). Файлы вида
_tools_X.py, которых нет, - типичная галлюцинация.
найти_файл после выбранного результата печатает секцию
"📋 Другие совпадения (пути):" - окно соседних путей (без
содержания), центрированное вокруг выбранного: при `номер: 50`
видны ~#35..#65. Параметр `других_путей` (по умолч. 30) -
размер окна. Края - "… и ещё N до/после".
Правило третье. Патч любого *.py - только с бэкапом:
  {"создать_бэкап": {"путь": "E:/путь/к/файлу.py"}}
Создаёт <путь>.bak_YYYYMMDD_HHMMSS рядом с файлом (или в в_папку).
Формат имени совпадает с удалить_старые_бэкапы - старые копии
потом чистятся штатно.
Readme.txt патчится тем же способом. README не hot-reload,
после правки - просто перезаписать и всё.
Правило четвёртое. Якоря для Replace - уникальные. Перед заменой
проверяй Count вхождений:
  ([regex]::Matches($txt, [regex]::Escape($anchor))).Count
Если больше одного - уточни якорь, иначе патч ударит не туда.
Правило пятое. Все патчи - одной |||-цепочкой, в одном блоке.
Если несколько заменить_текст / заменить_функцию не зависят друг от
друга (разные якоря, один патч не ломает якорь другого) - отдавай
их одной |||-цепочкой в ОДНОМ блоке ```json. Несколько отдельных
блоков в одном ответе - плохо: оператор выполняет ТОЛЬКО первый блок,
остальные теряются молча.
ВАЖНО: ||| ставится на ТОЙ ЖЕ строке, что закрывающие фигурные
скобки команды. Никаких переводов строки перед |||. Если поставить
||| первым символом новой строки - цепочка распадётся, выполнится
только последний блок (или anyjson вообще не разберёт ввод).
Проверено на convert.py: два патча из трёх потерялись именно из-за
перевода строки перед |||.
Зависимые патчи - тоже одной |||-цепочкой: ||| выполняется
последовательно, второй видит результат первого. Это ровно то же,
что отдельные блоки по одному, но оператор копирует один раз.
Проверяй каждый replaced в выводе. Отдельные ```json блоки - только
для: SOLO-команд (нельзя в |||), предпросмотра с контролем оператора
(сначала diff, потом применить) и альтернатив ("удалить или
переместить?" - выбирает оператор).

**Нет подтверждения = патч НЕ применён.** Если после заменить_текст /
заменить_функцию в выводе нет «✅ Заменено» или «⛔ Ошибка» - оператор
увлёкся и забыл выполнить команду. Это НЕ значит, что «наверное
применилось». Перед следующим шагом, который зависит от патча (запуск,
тест, ссылка на новый код), явно попроси подтверждение или проверь
факт: {"найти_файл": {"содержание": "<уникальная_строка_из_патча>"}}.
Типичная ошибка: отправил патч → молчание → предполагаешь, что оно уже
в файле → запускаешь старый код и удивляешься результату.
Правило шестое. anyjson не запускается - только PowerShell.
Если anyjson не стартует (валидатор, SyntaxError, guard), JSON-команды
бесполезны: их некому выполнять. Правки - через PS here-string
с проверкой якоря и бэкапом. Скрипт-образец - в истории сессий
(ReadAllBytes → GetString → Replace → py -m py_compile → WriteAllBytes).
Правило седьмое. Вложенные heredoc-маркеры поддерживаются (счётчик
глубины в anyjson.py, cmd_parser.py и _utils.py). Если нужно
напечатать одиночный маркер без пары - собирай через chr(60)*3 / chr(62)*3.
В _utils.split_preserving_quotes in_heredoc - счётчик int (не bool):
+=1 при открытии, -=1 при закрытии.
Правило восьмое. Отступы в якорях - точные.
В Python отступ = 4 пробела, но в разных функциях он разный
(метод класса - 8, вложенный блок - 12). Копируй якорь из вывода
"ближайшие совпадения" - там видно точное число пробелов.
Перед записью всегда предпросмотр: true; если в diff стоит
+r = ... без отступа - стоп, якорь/замена съехали.

Работа с пользователем (оператор)
---------------------------------
- Выполняет ТОЛЬКО первый блок в ответе, остальные теряются молча.
  Несколько патчей - одной |||-цепочкой в одном блоке.
- Докстринги - только существо (что, скорость, где плох); без путей
  и "внешний CLI".
- "Применение не найдено" лучше принудительной похвалы. "10/10" -
  только после проверки на реальном контенте.
- Язык ru. Скриншоты - через посмотреть_картинку (SOLO, первый блок).

Быстрый старт
-------------
cd E:\Jericho\Private\anyjson
py anyjson.py Ассистент
Без аргумента - спросит имя агента.
Профиль и рабочие файлы создаются в profiles\<Агент>\memory\.
---
Имя агента
Имя задаётся первым аргументом командной строки:
py anyjson.py Ассистент
py anyjson.py "Мой Агент"
Несколько аргументов склеиваются через пробел:
py anyjson.py Мой Агент      # то же, что "Мой Агент"
Без аргументов anyjson спросит имя интерактивно (_ask_name(), input("> ")).
В скрипте / subprocess / CI так нельзя - зависнет или упадёт с EOFError.
Всегда передавай имя первым аргументом.
Перед _sanitize_name имя проходит _extract_name: если есть
продолжение после первой . ! ? ; :, - хвост срезается.
"SAAI. Готов к работе." → SAAI, "SAAI." → SAAI. Также
понимает "Имя: X", "**X**", "меня зовут X", "My name is X".
Из имени вычищаются < > : " / \ | ? *, скобки, кавычки, запятые и управляющие
символы (_sanitize_name). Пробелы и дефисы остаются. Результат - имя папки
profiles\<Агент>\memory\.
Файл side\config.json обязателен - без него _config.py делает sys.exit(1)
с сообщением "Караул! Скрижаль Конфигурации утеряна".
Формат ввода
------------
Одна команда:
{"имя_команды": {"параметр": "значение"}}
Несколько команд: ||| (последовательно) или "параллельно" (одновременно).
||| - ставится вплотную к } предыдущей команды; после ||| можно
перейти на новую строку. ||| отдельной строкой → ❌ "Разделитель
||| не может быть на отдельной строке", ничего не выполняется.
"Продолжение следует", "каждая строка = команда с |||" - работают:
||| в конце каждой строки (после }), последняя - без. Многострочные
цепочки разрешены.
В одну строку:
{"эхо": {"текст": "hi"}}|||{"время": {}}|||{"погода": {"город": "Москва"}}
"параллельно" - ОДНОВРЕМЕННО (не по очереди), для зависимых шагов
не годится. Массив - обычный JSON, можно многострочно:
  {"параллельно": [
    {"эхо": {"текст": "a"}},
    {"эхо": {"текст": "b"}}
  ]}
Для зависимых шагов (результат одной нужен другой) - только |||,
и ||| вплотную к }, не отдельной строкой.
Короткая запись параметров
--------------------------
Если у команды один главный параметр, его можно передать голой строкой,
без обёртки в словарь. anyjson сам поймёт:
  {"читать_полностью": "E:/file.txt"} → {"читать_полностью": {"путь": "E:/file.txt"}}
  {"эхо": "привет"} → {"эхо": {"текст": "привет"}}
Работает для файловых команд из _PATH_COMMANDS (cmd_parser.py) — голая
строка уходит в "путь". Остальные команды — в {"запрос": ...} (не "текст",
как ошибочно обещала старая версия этого файла). _PATH_COMMANDS — единый
источник правды: используется и в _normalize_params, и в препроцессинге
_process_command_input_inner.

В пакетном режиме (несколько команд через |||, не менее двух) оператор
видит в консоли прогресс-метку `X/Y · имя_команды` перед запуском
каждой команды: `2/5 · заменить_текст`. Это для человека - в результаты
и в буфер обмена метка не попадает (агент её не видит). При одной
команде метка не печатается.
Если несколько JSON-команд введены подряд (каждая с новой строки,
без |||) - anyjson обнаружит их, выполнит последовательно и добавит
в результаты уведомление:
   ℹ️ Выполнено N команд последовательно.
      Параллельно: {"параллельно": [ ... ]}
      Отключить это уведомление: разделяйте команды через |||.
Многострочный JSON - копится в буфере. REPL ждёт, пока не закроются
все открытые { и [ (скобки считаются вне кавычек - { внутри строк
не мешает). Как только баланс сошёлся - выполняет сразу, без пустых
строк.
Одна пустая строка - принудительное выполнение, если по какой-то
причине баланс не сошёлся. Две - для ввода, не начинающегося с {.
Heredoc - для длинных текстов и кода
Все команды с телом принимают его через inline-heredoc - значение
поля оборачивается в <<< ... >>> прямо в JSON, без экранирования.
Примеры ниже.
Inline-heredoc (внутри JSON, для любой команды)
В любом строковом параметре любой команды можно писать <<<...>>>
прямо внутри JSON - значение подставится как строка, без экранирования.
Один ведущий и один хвостовой \n обрезаются; литерал >>> внутри
тела закроет блок раньше времени. ||| внутри <<<...>>> - часть тела,
а не разделитель команд: сплиттер не режет по |||, пока не закрыт >>>.
То же с кавычками внутри тела - не интерпретируются.
  {"заменить_текст": {"путь": "a.txt", "найти": <<<
  старый
  текст
  >>>, "заменить": <<<
  новый
  текст
  >>>}}
Работает для любой команды с текстовым параметром:
заменить_текст, заменить_функцию, переписать, добавить, питон и др.
Многострочный код для "питон":
  {"питон": {"скрипт": <<<
  import json
  print(json.dumps({"a": 1}))
  >>>}}
Если файла нет, `_file_not_found_msg` (system.py) теперь предлагает
сначала `{"переписать": ...}`, а затем `{"питон": ...}`. Старые
подсказки с отдельными `<<<` и `>>>` вычищены (2026-10-26).
Внутри <<<...>>> не оставляй 3 пустые строки подряд.
Автопочин незакрытых скобок в JSON
Если JSON не разобран, скобки несбалансированы (не хватает } или ]),
и мы не внутри строки - anyjson дописывает недостающие в конец и
выполняет повторно. В результатах появляется предупреждение без
номера - до списка выполненных команд:
  {"запомнить": {"содержимое": "текст"}
  Результаты:
     ⚠️ JSON не закрыт - автопочин добавил: } (возможно, забыл закрыть в конце?)
  1. Запомнил: текст
Если автопочин не помог - в ответе позиция ошибки, фрагмент вокруг
неё и счётчик незакрытых скобок. Запятые "на глаз" не подставляются:
если пропущена запятая между парами - обычная ошибка, без автопочина.
Автотрим лишней } в конце (Extra data)
Симметрично: если json.loads падает с Extra data и лишний символ -
это "}" в конце (e.pos указывает на него), anyjson пробует срезать
хвост и распарсить cleaned[:e.pos]. При успехе команда выполняется,
в результатах - предупреждение:
   ⚠️ Убрал лишнюю "}" в конце (Extra data). Проверь ввод.
Автотрим не маскирует структурные ошибки. После среза имена верхнего
уровня проверяются через _extract_actions: если появились неизвестные
команды (например, "таймаут" вместо параметра "питон") - срез
откатывается, в результатах honest hint "лишняя } стоит раньше, чем
показано, возможно сразу после маркера конца heredoc". Типичный
случай - лишняя } сразу после маркера конца heredoc.
Фрагмент ошибки в результатах показывает маркер <-!!ТУТ!!-> ровно в
позиции ошибки плюс хинт (лишняя } / ] / , / | / конец строки). Источник
истины - e.doc (то, что реально парсил json.loads), а не cleaned:
safe_json_parse может внутри манглить \" и сдвигать позицию, и срез
из cleaned тогда показывает не то место.
Shell-питон
Ввод вида `python girls.py "arg1" "arg2"` anyjson не выполняет.
Вместо этого - "❌ Не понял ввод" с готовым JSON-шаблоном для
команды "питон":
  💡 Похоже на запуск Python из консоли. В anyjson для этого есть
  команда "питон":
  {"питон": {"скрипт": "girls.py", "аргументы": "arg1 arg2"}}
Аргументы принимаются строкой (парсятся через shlex) или списком.
В подсказке system_ps.py теперь генерируется строковый вариант как более интуитивный.

Регистрация команд
------------------
from _actions import register
@register(["читать", "прочитать", "прочитай"])
def read_(args: dict) -> str:
    ...
    return "ответ"
HANDLERS[name] = func - для каждого имени.
HANDLERS и PRIMARY_HANDLERS
HANDLERS хранит все имена команд, включая алиасы (читай, прочти, шелл, stop).
PRIMARY_HANDLERS хранит только первое имя из каждого @register(...) - канонический вариант.
- Все алиасы работают - разницы для вызова нет.
- Подсказки (пакетный режим, случайные примеры, "Ты пробовал(а) команду X?")
  берутся из PRIMARY_HANDLERS, чтобы не мелькали алиасы.
Пример:
@register(["запуск", "терминал", "шелл"])
- HANDLERS: запуск, терминал, шелл - три записи, все ведут на одну функцию.
- PRIMARY_HANDLERS: только запуск.
Правило имён
Все имена команд - только на кириллице (плюс цифры и _).
Любая латиница в имени команды блокируется с подсказкой русского аналога:
❌ Команда "echo" - латинский алиас, используй русское имя:
  • "эхо"
Если латинское имя зарегистрировано, но у него есть кириллический брат-близнец -
подсказка покажет русское имя. Если нет - общая подсказка
❌ Название команды должно быть на русском, например: ....

Правки файлов (для LLM)
-----------------------
Инструменты точечных правок кода, докстрингов, конфигов.
- переписать (алиасы: перезаписать_файл, записать_файл, переписать_файл) - записать файл целиком. Параметры: путь, содержание
  (алиас содержимое), подтвердить_потерю (true - разрешить, если новый текст меньше старого). Без предпросмотра - пишет сразу;
  если файл существует - создаётся бэкап `<путь>.bak_YYYYMMDD_HHMMSS`
  (как у создать_бэкап); при ошибке бэкапа запись отменяется.
  Для безопасной правки - заменить_текст/заменить_функцию.
  Многострочный текст - heredoc (маркеры из трёх угловых скобок,
  см. "Формат ввода"); сами маркеры в теле патча не пиши.
- добавить - дописать в конец. Параметры: путь, содержание.
- заменить_текст - X → Y в файле. Параметры: путь, найти, заменить,
  все, регистр, регулярка, предпросмотр, показать_близкое,
  без_проверки.
  • гибкий поиск (всегда включён) - если точное совпадение не найдено,
    движок пробует вариант, где NBSP↔пробел, тире↔дефис, «»↔"",
    CRLF↔LF. Правится ТОЛЬКО найденный фрагмент, остальной файл
    не меняется.
  • без_проверки (по умолч. false) - для *.py: отключить предварительную
    проверку синтаксиса. Без флага правка .py, ломающая компиляцию,
    НЕ записывается: возвращается "⛔ Синтаксическая ошибка" с позицией
    и сниппетом. В предпросмотре - предупреждение + diff. Обход нужен
    для промежуточных правок в два прохода. При успешной проверке
    в ✅ и 👁 добавляется пометка "· синтаксис OK" (только для .py).
  • регулярка: true - find как regex; точка не матчит \n, блок - через
    [\s\S]*? (напр. "НАЧАЛО[\s\S]*?(?=КОНЕЦ)").
  • предпросмотр: true - diff и счётчик, файл не писать.
    Когда НЕ нужно: тривиальная правка (один известный якорь,
    замена уже проверена, .txt или .py с гарантированно чистым diff).
    Когда НУЖНО: регулярка, несколько вхождений (все: true на большом
    файле), сложный многострочный якорь, риск зацепить не то.
    Страховка и без предпросмотра: для *.py — проверка синтаксиса
    (сломанный код не пишется), после записи — diff в выводе,
    откат — из .bak_*.
  • показать_близкое (по умолч. true) - при replaced: 0 вывод начинается
    с "🔍 Первое расхождение" (строка, направление, repr лишнего);
    ближайшие строки с repr; без "сходства в %".
- заменить_функцию - заменить функцию по имени. Параметры: имя, путь,
  содержание (алиасы: содержимое, код). Бэкап + AST-проверка, сломанный код откатывается.
- найти_функцию - AST-поиск def в исходниках. Параметры: имя
  (подстрока или regex; если не задано - выводятся ВСЕ функции
  файла/папки списком, без тел, сортировка по файл:строка),
  регулярка, точно, тело, путь (_actions + _core + anyjson.py),
  количество. Показывает файл:строку; с телом: true - исходник.
  Удобно, когда не знаешь, где живёт функция, или нужно окинуть
  взглядом весь модуль.
- прочитать_функцию - прочитать одну функцию по имени (AST).
  Параметры: имя, путь (без пути - все _actions/*.py).
- проверить_синтаксис - проверить .py или строку без выполнения.
  Параметры: путь или скрипт.
- осмотреть (алиасы: осмотр, найти_в_файлах) - поиск по содержимому.
  Параметры: путь (алиас папка), ключевые_слова (алиас искать),
  количество, вокруг, регулярка (иначе подстрока), маска (алиас
  шаблон - glob-фильтр имён файлов, НЕ поиск по содержимому).
  Через side/inspect.ps1.
- создать_бэкап - копия файла <путь>.bak_YYYYMMDD_HHMMSS.
  Параметры: путь, в_папку (алиас куда), суффикс. Формат имени
  совместим с удалить_старые_бэкапы. Папки не бэкапятся.
- удалить_старые_бэкапы - чистка *.bak*. Параметры: папка (алиас путь),
  старше_дней (7), безопасно. Для каждого базового X: есть свежие -
  старые удаляются; все старые - остаётся самый новый. Timestamp из
  имени (X.bak_TS / X_TS.bak / X.bakTS) или mtime. безопасно: true -
  только предпросмотр.
- дедуплицировать_строки - удалить повторяющиеся строки.
  Алиасы: убрать_дубли_строк, dedupe_lines. Параметры: путь (алиас файл),
  сохранить (алиас выход; по умолч. перезапись), подряд (true - только
  подряд; false - все дубли с первым вхождением), пустые (false - не
  считать дублями), пробелы (true - после strip()), нестрого
  (нормализация NBSP/кавычек/тире), предпросмотр (только показать),
  перезаписать (разрешить запись в существующий "сохранить").
  Кодировку и CRLF/LF сохраняет. Возврат: "Удалено N строк (было X,
  стало Y)". Для кода осторожно: две подряд "pass"/"return None"
  могут быть осмысленны - предпросмотр: true.
- not_a_file_msg (в _core/_utils.py) - единое сообщение для file-only
  команд, которым дали папку вместо файла. Показывает шаблоны
  список_файлов (плоский и рекурсивный) + необязательный extra
  (у создать_бэкап - "(бэкап папок не поддерживается - только файлы)").
  Не дублируй "❌ Это не файл" в новых модулях - импортируй
  from _utils import not_a_file_msg. Пять копий уже свели в один
  (files, files_replace, image_mask, tools_backups, video, 2026-11-09).
  Путь в шаблонах нормализуется заменой обратного слэша на прямой,
  иначе Path() даёт невалидный JSON и \f съедает букву.
Подсказка при ошибке
AssertionError в патч-скрипте - якорь не найден. Для точечных
правок удобнее заменить_текст с предпросмотр: true (diff до записи)
и регулярка: true
(если якорь сложный). Если assert упал на якоре - НЕ перебирай
якоря через питон: покажи оператору осмотреть / найти_функцию,
пусть найдёт актуальный фрагмент.
Hot-reload
----------
Правки в файлах подхватываются на лету при следующей ПАЧКЕ команд
(не внутри текущей |||-цепочки). Reload срабатывает до разбора
следующей отправки, а не посреди текущей: патч и проверка в одном
|||-блоке - проверка увидит СТАРЫЙ код. Тестировать отдельной
отправкой.
| Файл | Поведение |
| _actions/*.py | ✅ reload |
| _core/_utils.py | ✅ reload |
| _core/_color.py | ✅ reload |
| _core/_executor.py | ✅ reload |
| _core/_ps.py | ✅ reload, _ps_cwd сохраняется |
| _core/_config.py | ⚠️ предупреждение, нужен перезапуск |
| _core/_storage.py | ⚠️ перезапуск |
| _core/_tor.py | ⚠️ перезапуск |
| _core/_safe_subprocess.py | ⚠️ перезапуск |
| _core/_web.py | ⚠️ перезапуск |
| _core/_py_guard.py | ✅ подхват сразу, без warn (_CORE_SILENT) |
| anyjson.py | ❌ не отслеживается |
Правило: не делай from X import y в anyjson.py
reload переисполняет код в том же объекте модуля, но не трогает
локальные ссылки, скопированные через from X import y. То есть:
- import _actions.cmd_parser as _cmd_parser → reload работает,
  потому что _cmd_parser.process_command_input резолвится в момент вызова.
- from _actions.cmd_parser import process_command_input → reload не работает,
  потому что process_command_input - это старая ссылка на функцию.
Правило: в anyjson.py (и в _core/*.py, которые он импортирует)
всегда import X + X.foo(), а не from X import foo.
Пример: _cmd_parser.process_command_input(...) вместо
process_command_input(...).

Фильтры безопасности
--------------------
Страж subprocess (_core/_safe_subprocess.py)
Любой .py можно запустить только внутри BASE_DIR.
Исключение - контекст allow_external_py(), который выставляет только
команда "питон".
- Чужой .py → ExternalPyBlocked.
- python -c "..." (inline) → пропускается.
- python -m module → пропускается.
- Не-питоновые команды (ffmpeg, curl, cleanmgr, ...) → не трогает.
Покрытие (с 24.09.2026):
- subprocess.run / Popen / call / check_output / check_call
- os.system
- os.popen
- shell=True со строкой: "python x.py", "echo hi && python x.py"
- имена python, python3, python3.11, python.exe, py, pyw - распознаются
Запрет записи
{"переписать"} и {"добавить"} запрещают запись в:
- C:\Windows
- C:\Program Files
- C:\Program Files (x86)
- C:\ProgramData
- Чужой профиль агента (profiles/<ДругойАгент>/...) - запись
  запрещена, если anyjson запущен под другим агентом
  (⛔ Запись запрещена: чужой профиль).
Ограничения {"питон"}
Regex-блок по тексту скрипта (быстрый отказ до запуска процесса):
os.system, subprocess, eval, exec, socket, requests, shutil.rmtree.
Плюс audit hook (_core/_py_guard.py). Команда "питон" запускает
скрипт не напрямую, а через guard, который ставит sys.addaudithook
и блокирует:
- запись (open на w/a/x/+), удаление, переименование и rmtree
  в системных папках (C:\Windows, C:\Program Files, C:\ProgramData,
  C:\$Recycle.Bin, C:\Recovery, C:\Boot и т.п.);
- любые os.system, os.exec;
- subprocess.Popen - за исключением ffmpeg/ffprobe из доверенных
  каталогов: dirname(config.paths.ffmpeg_exe / ffprobe_exe),
  site-packages, бандл imageio-ffmpeg. argv с shell-метасимволами
  (& | ; < > ( )) и shell=True блокируются всегда. В сообщении о
  блоке видно имя бинаря (например, subprocess.Popen (notepad.exe));
- любой shutil.rmtree - независимо от пути.
Нарушение → одна строка в stderr + os._exit(3), без traceback
и без утечки имени guard-файла. os._exit не ловится try/except,
скрипт умирает, даже если попытается проглотить ошибку.
Guard - НЕ sandbox. Нативные вызовы (ctypes, win32com/pythoncom)
audit hook не видит: WScript.Shell.Run запустит процесс мимо
блокировки subprocess, Shell.Application скопирует/удалит файлы
мимо open(). "питон" - доверенный канал для кода оператора,
а не изоляция агента. Не советуй агенту питон-скрипты с
непроверенным кодом; для штатных задач - встроенные команды.
Режим в_файл (только у {"питон"}):
- вывод скрипта идёт и в консоль оператора, и в указанный файл;
  в контекст (в результат команды) - только короткая сводка;
- если скрипт упал сам (SyntaxError, IndentationError, Traceback,
  non-zero exit) - файл НЕ создаётся, вывод идёт в контекст как у
  обычного "питон";
- если вывод меньше 1 КБ - в сводке подсказка, что "в_файл" тут
  избыточен.
Guard не только блокирует, но и даёт подсказки - куда идти вместо
запрещённого вызова:
- shutil.rmtree → удалить_папку / удалить_путь / удалить_пустые_папки
  / убраться_в
- os.system / subprocess.Popen / os.exec → {"запуск": {"команда": ...}}
  или {"питон": {"скрипт": "demo.py", "аргументы": ["arg1"]}}
- запись в защищённую папку → переписать / добавить
- удаление/переименование в защищённой папке → удалить_файл / переместить
Зачем hook поверх regex: regex ловит "os.system" текстом и обходится
через "from os import system", "importlib", "getattr". Hook ловит
событие на уровне интерпретатора и не обходится. Regex остаётся
как быстрый слой (не тратить время на старт Python ради отказа).
leak_guard
Блокирует отправку во внешние сервисы (Moltbook, UNaIVERSE) текста с секретами:
- password, passwd, pwd, passphrase,
- api_key, apikey,
- private_key, secret_key,
- token, secret, bearer, authorization,
- форматы: sk-..., xoxb-..., ghp_..., Bearer ..., длинные hex (40+).
Маскировка вывода (mask_secrets)
tools_leak_guard.mask_secrets() вызывается в cmd_parser._mask() и _ps._mask()
- любой вывод команды, до печати и до копирования в буфер.
Заменяет на *:
- email (любой),
- sk-..., xoxb-..., ghp_..., Bearer ...,
- длинные base64url-строки (≥40 символов, не чистый hex, ≥3 категории из
  {верхний, нижний, цифры, -/_}).
Это маскировка вывода, не блокировка. leak_guard блокирует отправку,
mask_secrets - маскирует в показе.
Email маскируется в выводе, но при отправке во внешние сервисы не блокируется
- это идентификатор, не секрет.

Tor
---
- ControlPort 9051 - для ротации exit-нод (stem, NEWNYM).
- torrc - в конфиге (_TORRC). Добавлены:
ControlPort 9051
  CookieAuthentication 0
  MaxCircuitDirtiness 60
  NewCircuitPeriod 30
- new_circuit(wait_sec=2.0) - запросить новую exit-ноду.
- Retry в Moltbook - при CloudFront 403 и timeout (до 10 попыток с ротацией).
  Бюджет одной операции - `_MOLTBOOK_DEADLINE = 60.0` в
  _tools_moltbook.py: токен и сам запрос делят ОДИН deadline,
  per-attempt timeout ужимается до остатка (≤30 с). Исчерпание →
  RuntimeError "бюджет Nс исчерпан (K попыток)" вместо зависания
  (раньше было до ~10 мин).
- `молтбук_кто_я` - свой бюджет 30 с + прогресс-бар (только TTY).
  Бар печатает `\r`, не `\\r`; если рисуется кусками - в файле
  удвоенный бэкслеш, чинить точечной заменой с `предпросмотр: true`.
- new_circuit в _tor.py открывает ControlPort с `connect_timeout=3`
  (stem не висит на мёртвом 9051).
- Tavily - только через Tor (socks5h://127.0.0.1:9050). Напрямую из РФ → 403.
- DNS через Tor - везде socks5h://, а не socks5://. Это значит, что имя
  сайта резолвится на стороне Tor, а не локально. Спасает, когда локальный DNS
  отдаёт IPv6 первым или вообще падает.
тор_запрос - всегда через Tor
Алиас веб_запроса, но авто_прокси: true жёстко вшит. Параметр авто_прокси
игнорируется. Все остальные параметры (метод, заголовки, тело,
сохранить_как, таймаут, страница, размер, обновить) - как у веб_запрос.
{"тор_запрос": {"адрес": "http://check.torproject.org/", "таймаут": 30}}
{"тор_запрос": {"адрес": "http://www.insecam.org/en/bycountry/RU/", "таймаут": 120, "обновить": true}}
{"тор_запрос": {"адрес": "https://api.example.com/data", "метод": "POST",
                "тело": {"ключ": "значение"}, "таймаут": 60}}
Где использовать: Insecam, Cloudflare-домены, любые сайты, которые блокируют
российские IP, - а также когда локальный DNS сбоит, а через Tor всё работает.

Установка Python-пакетов (установить_пакет)
-------------------------------------------
pip без выхода в PowerShell. PyPI по умолчанию или PyTorch-индекс.
  {"установить_пакет": {"имя": "thorvg-python[full]"}}
  {"установить_пакет": {"имя": "torch==2.9.0+cu128",
                        "индекс": "pytorch", "таймаут": 1800}}
Параметры:
- имя      - имя пакета (обязательно), с extras и опц. версией:
             "thorvg-python", "thorvg-python[full]",
             "torch==2.9.0", "torch==2.9.0+cu128", "numpy==2.1.*".
             Только "==" (фиксация/wildcard); >=, <=, ~= - блок.
- индекс   - URL индекса pip (алиасы: index_url, источник).
             https, домен из _ALLOWED_INDEX_HOSTS (в коде):
             pypi.org, download.pytorch.org. Сокращения: "pypi",
             "pytorch" (→ cu128). Без индекса - дефолт pip.
- таймаут  - секунд (по умолч. 300, макс 1800).
Поведение pip:
- ЛЮБАЯ другая версия → pip сам сносит старую и ставит новую
  (включая даунгрейд и смену local-тега "+cu121" → "+cu128").
- Точно та же строка уже стоит → "Requirement already satisfied",
  не переустанавливает (--force-reinstall не поддерживается).
- pip uninstall не вызывается: удалить пакет эта команда не умеет.
Защита:
- имя: regex с опц. ==version, блок подстрок (URL, слеши,
  shell-метасимволы, пробелы, --index-url и т.п.);
- индекс: отдельный канал. Схема строго https, host из
  _ALLOWED_INDEX_HOSTS, без user:pass@, без "..", без query/fragment.
  Расширение whitelist'а - задача оператора/LLM, не агента.
- вызов строго [sys.executable, "-m", "pip", "install", <имя>]
  (опц. + ["--index-url", <валидированный>]) - без shell.
Принцип: никаких тихих операций. Поток pip идёт в консоль в
реальном времени всегда; "тихо": true не поддерживается.
pip в whitelist "запуск" НЕ добавлен - установка только через эту
команду.
pip ставит в user-site, если системный site-packages не writable без админа.

SOLO_COMMANDS
стабилдиф, нарисуй, сгенерировать, txt2img, перерисуй, дорисуй,
убрать_фон, кроп, зеркало, слои, окно_в_мир, смотреть_видео,
посмотреть_картинку, прочитать_полностью и другие - в множестве
SOLO_COMMANDS в cmd_parser.py. Эти команды переписывают контекст.
Правила:
- В ||| SOLO нельзя вообще (ни в начале, ни в середине, ни в конце):
  результат SOLO переписывает контекст и затирает всё, что было до
  неё. Исключение - "в_контекст": false (или старый "в_буфер": false):
  тогда SOLO не трогает контекст и её можно ставить в любую позицию.
- Внутри "параллельно" - строгий режим: SOLO-команды разрешены
  только с "в_контекст": false. Иначе блок.
- NO_CTX_FALSE - команды, которые НЕ принимают "в_контекст": false
  (результат только в контекст): смотреть_видео, посмотреть_движение,
  прочитать_полностью, читать_полностью, показать_файл, рендер, отрендерить, открыть.
  В ||| (при >1 команде) и в параллельно запрещены. Исключение -
  read_full-команды (прочитать_полностью, читать_полностью, открыть, показать_файл,
  посмотреть_файл, посмотреть_картинку, рендер, отрендерить,
  svg_в_буфер, рендер_svg) в параллельно: если ВЕСЬ батч состоит
  только из них, разрешены без в_контекст:false (system_parallel
  сольёт в один Set-Clipboard -Path). Смешанный батч (read_full +
  обычные команды) - блок: read_full уйдёт в буфер, обычные - в
  контекст, агент получит [BUF] вместо содержимого файла. Если
  параметр в_контекст:false всё же передан - предупреждение + пропуск
  только этой |||-части, остальные команды выполняются. Если команда
  одна - только предупреждение, ничего не выполняется.
- NO_CTX_FALSE_NEEDS_SAVE - команды, у которых "в_контекст": false
  допустим только при наличии "сохранить": слушать_видео,
  кадр+субтитр, кадр. Без сохранения - отказ с требованием "сохранить".
- Алиас "кадр" (для "кадр+субтитр") идёт с "субтитр": false по
  умолчанию - без выжигания субтитров. SOLO-защита и
  NO_CTX_FALSE_NEEDS_SAVE работают и для алиаса.
- У "кадр", "кадр+субтитр", "слушать_видео": если задан "сохранить",
  буфер по умолчанию не трогается (только файл). Явный
  "в_контекст": true - и файл, и буфер.
- Проверка в _collect_all_actions, _iter_solo_checks, _params_are_safe.
Пример: несколько "сгенерировать" в одном параллельно, только
на диск, буфер не трогают:
  {"параллельно": [
    {"сгенерировать": {"промпт": "...", "сохранить": "C:/s/01.png", "в_контекст": false}},
    {"сгенерировать": {"промпт": "...", "сохранить": "C:/s/02.png", "в_контекст": false}}
  ]}

Команды и справка
-----------------
Полный список: {"список_команд": {}}. Поиск: {"диагностика": {"сервис": "..."}} (понимает транслит: moltbook <-> молтбук).
Докстринг команды автоматически добавляется к ошибке выполнения.
Алиасы параметров (автоматически дублируются): лимит<->количество, url<->ссылка<->адрес, запрос<->query, папка<->путь, искать<->ключевые_слова, шаблон<->маска.
Команды с произвольными ключами помечены _any_params = True (например, предсказать_продолжение, молтбук_запрос).
Принцип: если агент сгенерировал логичный и безопасный параметр, которого нет в коде — добавь его как алиас, а не отбивай ошибкой.
Никаких тихих операций: параметр тихо/silent не поддерживается. Долгие операции всегда печатают прогресс.

Диагностика и частые грабли
---------------------------
• Hot-reload: _actions/*.py и часть _core/* подхватываются МЕЖДУ пакетами команд, не внутри текущей |||-цепочки.
• Падение импорта _actions-модуля = тихая потеря всех его команд. Проверяй {"диагностика": {"сервис": "<команда>"}} после правки.
• py_compile / "синтаксис OK" ловит только SyntaxError, но НЕ runtime-ошибки (ValueError в f-строках, распаковка кортежей). Проверяй запуском.
• Якорь для патча бери из факта (прочитать_функцию/осмотреть ПОСЛЕ последнего патча), а не из памяти о прошлом коде.
• JSON с путями: используй только прямые слэши (E:/path). Обратный слэш в JSON-строке — это escape (\f съедает f).
• Имя агента всегда первым аргументом (py anyjson.py Имя). Без него _ask_name() зависнет в CI/subprocess.
• IPv4-only резолв: _config.py переопределяет socket.getaddrinfo только на AF_INET, чтобы избежать ошибок при сломанном IPv6 DNS.
• file-only команда на директории (рендер, создать_бэкап и т.п.) -> not_a_file_msg с шаблонами список_файлов, без докстринга.

Специфичные команды (суть, детали — в докстрингах)
--------------------------------------------------
• Lottie (текстурировать_лотти, конвертировать_лотти, лотти_в_видео): скрипты в side/external/lottie/. Бюджет рендера — 60с.
• Видео (обрезать, склеить, наложить_звук, морф, затухание, Ken Burns, апскейл): пути от config.json или абсолютные. склеить без перекодировать: true требует одинаковых кодеков/FPS.
• Stable Diffusion (Forge): запуск ТОЛЬКО через run.bat (он подсовывает встроенный Python). Прямой запуск webui-user.bat создаст мусорный venv. Патч scripts/api.py для forge2_cleaner откатывается при обновлении.
• Удаление текста (убрать_текст): DBNet -> маска -> inpaint (LaMa/SD). Модели в E:\StableDif\models\text_detection\ и forge2_cleaner\models\.
• Сжатие текста (сжать_текст): rut5-squeeze (T5), локально. Защиты: откат, если пропали числа/пути, нарушен баланс скобок или стало длиннее.
• Архивы (распаковать): zip/tar на stdlib. 7z/rar — ошибка с подсказкой. Zip-slip защита включена.
• Симулятор (PyBullet), Дзен (Playwright), UNaIVERSE: файлы состояния в MY_DIR. UNaIVERSE agent-to-agent не работает (их баг).

=== ВЕБ-ИНТЕРФЕЙС (Web Server) ===========================================================================
======================================================================
Запуск:
py E:\Jericho\Private\anyjson\web_server.py
Адрес в браузере:
http://127.0.0.1:8081
Архитектура:
• web_server.py - тонкая обёртка, тянет _core/_server.py.
• _server.py - HTTP + SSE + оркестрация цикла модель↔демон.
• _core/web_ui.html - фронтенд (читается при каждом запросе,
  правки дизайна видны по F5 без перезапуска сервера).
• _core/command_stats.json - статистика вызовов команд (топ-5).
Демон agent.py:
• Запускается один раз при старте сервера (subprocess.Popen, --daemon).
• stdin/stdout - построчный JSON (один ключ = одна команда).
• _call_agent_daemon() фильтрует служебный шум: строки [DEBUG], "Результаты:", "Результаты скопированы в буфер обмена" - вырезаются,
 модель видит только чистые данные.
• Hot-reload для `_actions/*.py` работает и в веб-режиме: демон вызывает
 `reload_if_changed()` между командами (см. раздел Hot-reload).
Цикл модель↔демон (do_GET /api/chat):
• MAX_TOOL_ITERATIONS = 5. На 5-м шаге к результату дописывается "Количество шагов исчерпано. Дай ответ пользователю..." и
 включается force_text_only - следующий ответ модели не парсится
 на инструменты, просто стримится как финальный текст.
• Tools API (строго нативный от llama.cpp):
• _build_tools() собирает массив tools: search_commands + execute_command
 + топ-5 частых команд из статистики.
• stream_llm() парсит delta.tool_calls из SSE-ответа, yield
 {"type": "tool_call", "name": ..., "arguments": ...}.
• Fallback-парсинг JSON из текста (_detect_json) полностью удалён.
 Модель обязана использовать нативный tools API, system prompt минимизирован.
• Маршрутизация в do_GET:
  - search_commands({"query": "..."}) → {"диагностика": {"сервис": "..."}}
  - execute_command({"name": "...", "arguments": {...}}) → {"...": {...}}
  - топ-5 напрямую: {"время": {}}
• Валидация имён команд - на стороне agent.py (демона), сервер не фильтрует.
Статистика команд (_core/command_stats.json):
• Скользящее окно из 3 сессий (сессия = запуск _server.py).
• При старте добавляется новая сессия, старая удаляется если >3.
• _record_command() пишет в текущую (последнюю) сессию после каждого
  успешного вызова демона.
• _get_top5() - сумма counts по всем 3 сессиям, сортировка по убыванию,
  добор из fallback_top5: ["время", "справка", "профиль_свой",
  "список_команд", "эхо"].
UI (web_ui.html):
• Счётчик токенов в истории (эвристика: длина/3, мысли исключаются).
• Автопрокрутка через requestAnimationFrame + флаг scrollPending.
• Мысли сворачиваются по завершении генерации (▾ → ▸).
• Таймер генерации в топбаре (performance.now, обновляется каждые 100 мс).
• Черновик ввода сохраняется в localStorage ('aj_draft').
• Панель активности агента: статус (ожидание/генерация/инструмент),
  последний результат, flash-анимация при вызове.
• Кнопки "Система" (drawer с system prompt), "Копировать", "↓ к последнему".
• Кастомные скроллбары, аврора+зерно фон, ролевые цвета сообщений,
  prefers-reduced-motion.
Безопасность:
• Сервер слушает только 127.0.0.1, доступ извне закрыт.
• Корректная остановка: Ctrl+C gracefully завершает HTTP-сервер и демон.
Остановка:
Нажмите Ctrl+C в окне консоли.
