anyjson
=======

Инструмент, которым внешний LLM (DeepSeek, GPT и т.п.) пользуется через JSON-команды.
Пользователь вводит JSON в консоль anyjson — команды выполняются. Обратной связи
«LLM внутри anyjson» нет, LLM снаружи.

---

Быстрый старт
-------------

cd E:\Jericho\Private\anyjson
py anyjson.py Ассистент

Без аргумента — спросит имя агента.
Профиль и рабочие файлы создаются в profiles\<Агент>\memory\.

---

Имя агента

Имя задаётся первым аргументом командной строки:

py anyjson.py Ассистент
py anyjson.py "Мой Агент"

Несколько аргументов склеиваются через пробел:

py anyjson.py Мой Агент      # то же, что "Мой Агент"

Без аргументов anyjson спросит имя интерактивно (_ask_name(), input("> ")).
В скрипте / subprocess / CI так нельзя — зависнет или упадёт с EOFError.
Всегда передавай имя первым аргументом.

Из имени вычищаются < > : " / \ | ? *, скобки, кавычки, запятые и управляющие
символы (_sanitize_name). Пробелы и дефисы остаются. Результат — имя папки
profiles\<Агент>\memory\.

Файл side\config.json обязателен — без него _config.py делает sys.exit(1)
с сообщением «Караул! Скрижаль Конфигурации утеряна».

Формат ввода
------------

Одна команда:

{"имя_команды": {"параметр": "значение"}}

Несколько команд в одной строке — через |||:

{"эхо": {"текст": "hi"}}|||{"время": {}}

Многострочный JSON — копится в буфере. Для выполнения нужно две пустые строки
(для JSON, начинающегося с { или ``, достаточно одной).

Heredoc — для длинных текстов и кода

{"переписать": {"путь": "C:/temp/x.py"}}
<<<
import os
x = "любые кавычки"
print(x)
>>>

Правила:

- <<< открывает блок;
- >>> закрывает и сразу выполняет (пустая строка после — не нужна);
- три пустые строки подряд — аварийное прерывание heredoc (без >>>);
- >>>|||команда — закрыть и сразу выполнить ещё одну команду через |||;
- внутри блока ничего не экранируется;
- то же работает для {"питон": {"скрипт": "X"}}.

Импорты

anyjson.py добавляет в sys.path:

- _CORE (_core/) — для _config, _utils, _executor, _ps, _tor, _storage, _web, _safe_subprocess.
- _HERE (anyjson/) — для _actions.

Пакет tools и старый tools.py удалены. Всё, что было там, переехало в
_actions/_tools_*.py и _actions/tools_*.py.

Регистрация команд
------------------

from _actions import register

@register(["читать", "прочитать", "прочитай"])
def read_(args: dict) -> str:
    ...
    return "ответ"

HANDLERS[name] = func — для каждого имени.

HANDLERS и PRIMARY_HANDLERS

HANDLERS хранит все имена команд, включая алиасы (читай, прочти, шелл, stop).
PRIMARY_HANDLERS хранит только первое имя из каждого @register(...) — канонический вариант.

- Все алиасы работают — разницы для вызова нет.
- Подсказки (пакетный режим, случайные примеры, «Ты пробовал(а) команду X?»)
  берутся из PRIMARY_HANDLERS, чтобы не мелькали алиасы.

Пример:

@register(["запуск", "терминал", "шелл"])

- HANDLERS: запуск, терминал, шелл — три записи, все ведут на одну функцию.
- PRIMARY_HANDLERS: только запуск.

Правило имён

Все имена команд — только на кириллице (плюс цифры и _).
Любая латиница в имени команды блокируется с подсказкой русского аналога:

❌ Команда "echo" — латинский алиас, используй русское имя:
  • "эхо"

Если латинское имя зарегистрировано, но у него есть кириллический брат-близнец —
подсказка покажет русское имя. Если нет — общая подсказка
❌ Название команды должно быть на русском, например: ....

Hot-reload
----------

Правки в файлах подхватываются на лету при следующей команде:

| Файл | Поведение |
| _actions/*.py | ✅ reload |
| _core/_utils.py | ✅ reload |
| _core/_color.py | ✅ reload |
| _core/_executor.py | ✅ reload |
| _core/_ps.py | ✅ reload, _ps_cwd сохраняется |
| _core/_config.py | ⚠️ предупреждение, нужен перезапуск |
| _core/_storage.py | ⚠️ перезапуск |
| _core/_tor.py | ⚠️ перезапуск |
| _core/_safe_subprocess.py | ⚠️ перезапуск |
| _core/_web.py | ⚠️ перезапуск |
| anyjson.py | ❌ не отслеживается |

Правило: не делай from X import y в anyjson.py

reload переисполняет код в том же объекте модуля, но не трогает
локальные ссылки, скопированные через from X import y. То есть:

- import _actions.cmd_parser as _cmd_parser → reload работает,
  потому что _cmd_parser.process_command_input резолвится в момент вызова.
- from _actions.cmd_parser import process_command_input → reload не работает,
  потому что process_command_input — это старая ссылка на функцию.

Правило: в anyjson.py (и в _core/*.py, которые он импортирует)
всегда import X + X.foo(), а не from X import foo.

Пример: _cmd_parser.process_command_input(...) вместо
process_command_input(...).

Фильтры безопасности
--------------------

Страж subprocess (_core/_safe_subprocess.py)

Любой .py можно запустить только внутри BASE_DIR.
Исключение — контекст allow_external_py(), который выставляет только
команда «питон».

- Чужой .py → ExternalPyBlocked.
- python -c "..." (inline) → пропускается.
- python -m module → пропускается.
- Не-питоновые команды (ffmpeg, curl, cleanmgr, ...) → не трогает.

Запрет записи

{"переписать"} и {"добавить"} запрещают запись в:

- C:\Windows
- C:\Program Files
- C:\Program Files (x86)
- C:\ProgramData

Ограничения {"питон"}

В тексте скрипта блокируются слова: os.system, subprocess, __import__,
eval, exec, socket, requests.

leak_guard

Блокирует отправку во внешние сервисы (Moltbook, UNaIVERSE) текста с секретами:

- password, passwd, pwd, passphrase,
- api_key, apikey,
- private_key, secret_key,
- token, secret, bearer, authorization,
- форматы: sk-..., xoxb-..., ghp_..., Bearer ..., длинные hex (40+).

Маскировка вывода (mask_secrets)

tools_leak_guard.mask_secrets() вызывается в cmd_parser._mask() и _ps._mask()
— любой вывод команды, до печати и до копирования в буфер.

Заменяет на *:

- email (любой),
- sk-..., xoxb-..., ghp_..., Bearer ...,
- длинные base64url-строки (≥40 символов, не чистый hex, ≥3 категории из
  {верхний, нижний, цифры, -/_}).

Это маскировка вывода, не блокировка. leak_guard блокирует отправку,
mask_secrets — маскирует в показе.

Email маскируется в выводе, но при отправке во внешние сервисы не блокируется
— это идентификатор, не секрет.

Tor
---

- ControlPort 9051 — для ротации exit-нод (stem, NEWNYM).
- torrc — в конфиге (_TORRC). Добавлены:

ControlPort 9051
  CookieAuthentication 0
  MaxCircuitDirtiness 60
  NewCircuitPeriod 30

- new_circuit(wait_sec=2.0) — запросить новую exit-ноду.
- Retry в Moltbook — при CloudFront 403 и timeout (до 10 попыток с ротацией).
- Tavily — только через Tor (socks5h://127.0.0.1:9050). Напрямую из РФ → 403.
- DNS через Tor — везде socks5h://, а не socks5://. Это значит, что имя
  сайта резолвится на стороне Tor, а не локально. Спасает, когда локальный DNS
  отдаёт IPv6 первым или вообще падает.

тор_запрос — всегда через Tor

Алиас веб_запроса, но авто_прокси: true жёстко вшит. Параметр авто_прокси
игнорируется. Все остальные параметры (метод, заголовки, тело,
сохранить_как, таймаут, страница, размер, обновить) — как у веб_запрос.

{"тор_запрос": {"url": "http://check.torproject.org/", "таймаут": 30}}
{"тор_запрос": {"url": "http://www.insecam.org/en/bycountry/RU/", "таймаут": 120, "обновить": true}}
{"тор_запрос": {"url": "https://api.example.com/data", "метод": "POST",
                "тело": {"ключ": "значение"}, "таймаут": 60}}

Где использовать: Insecam, Cloudflare-домены, любые сайты, которые блокируют
российские IP, — а также когда локальный DNS сбоит, а через Tor всё работает.

UNaIVERSE
---------

Пакет unaiverse (0.1.12) — P2P-сеть агентов.

Команды

| Команда | Что делает |
| юнайверс_остановить | мягко остановить |
| юнайверс_статус | статус + хвост лога |
| юнайверс_лог | хвост лога с фильтром и контекстом |
| юнайверс_найти | глобальный список узлов (/nodes/get) |
| юнайверс_подключиться | подключиться к агенту |
| юнайверс_войти_в_мир | войти в мир |
| юнайверс_покинуть | покинуть всё |
| юнайверс_входящие | прочитать inbox |
| юнайверс_ответить | отправить текст |
| юнайверс_запрос | прямой POST к /api/... |

Демон стартует автоматически при обращении к юнайверс_поиск,
юнайверс_найти, юнайверс_подключиться, юнайверс_войти_в_мир,
юнайверс_покинуть, юнайверс_ответить, юнайверс_входящие.
НЕ поднимают демон: юнайверс_статус (проверка), юнайверс_лог
(чтение файла), юнайверс_остановить, юнайверс_запрос (прямой API).
Команда юнайверс_запустить убрана. Долгие команды
(подключиться, войти_в_мир, покинуть) показывают прогресс-бар.

Особенности

- Agent(HumanModule with explicit streams) — text-only.
  Не объявляем img-выход, иначе UNaIVERSE открывает камеру (cv2.VideoCapture(0)).
- asyncio.sleep ≥ 0.05s — их главный цикл вызывал sleep(0.001) и жёг ядро.
- prompt_toolkit.patch_stdout → no-op, prompt() → заглушка. Иначе падает
  на отсутствии консоли.
- stdin=DEVNULL у демона — чтобы не перехватывал REPL-ввод.
- NODE_IGNORE_ALIVE=1 — обход серверной блокировки имени (безопасно, потому
  что мы сами гарантируем отсутствие дублей через PID-файл и _kill_orphan_agents).
- Демон запускается с CREATE_NO_WINDOW, но при этом CREATE_NEW_PROCESS_GROUP.
- Файлы обмена (в MY_DIR): unaiverse_cmd.jsonl, unaiverse_result.jsonl,
  unaiverse_inbox.jsonl, human_input.txt, unaiverse.log, unaiverse.pid.

Известные ограничения (v0.1.12)

- Agent-to-agent P2P не работает — ask_to_get_in_touch падает с
  Connection failed! до ping-pong (relay misc.unaiverse.io не пропускает
  агент-агент трафик).
- Браузер ↔ агент тоже не работает — та же проблема.
- World join работает (ChatRoom подключался), но broadcaster молчит.

Это баг их платформы, не наш. Ждём обновления.

Stable Diffusion (Forge)
------------------------

Генерация картинок через локальный Forge (форк A1111).

Путь и конфиг

В side/config.json:

{
  "paths": {
    "stabledif_dir": "E:/StableDif"
  }
}

В _config.py оттуда растут STABLEDIF_DIR, STABLEDIF_RUN,
STABLEDIF_HOST, STABLEDIF_PORT. Никаких хардкодов в *.py.

Запуск

webui-user.bat:

set COMMANDLINE_ARGS=--api --server-name 127.0.0.1 --port 7860

- --api — REST API включён
- --server-name 127.0.0.1 — слушает только локально
- --port 7860

нарисуй сам поднимает Forge, если API не отвечает. Руками run.bat
дёргать не надо. Прогресс старта: Forge стартует... Ns ####.
После первого запуска Forge остаётся в фоне — следующий нарисуй мгновенный.


Параметры нарисуй

- промпт — обязательно
- негатив
- ширина / высота — по умолчанию 512×512
- шаги — sampling steps, по умолчанию 20
- cfg — CFG Scale, по умолчанию 7.0
- seed — по умолчанию -1 (случайный)
- сэмплер — Euler a по умолчанию
- модель — имя чекпойнта, переключает на лету
- в_буфер — true по умолчанию
- сохранить — путь для PNG (иначе MY_DIR/stabledif_out/)

Пример:

{"нарисуй": {"промпт": "cat in a hat, oil painting",
             "негатив": "blurry, low quality",
             "ширина": 768, "высота": 768, "шаги": 30}}

Прогресс

Во время генерации — Осталось N сек. (обновляется в той же строке, не спамит).
ETA берётся из /sdapi/v1/progress.

BUF_COMMANDS

стабилдиф, нарисуй, сгенерировать, txt2img — в списке BUF_COMMANDS
в cmd_parser.py. Их нельзя смешивать с другими командами в |||
(гонка за буфер). Отдельной командой.

Файлы

- PNG: profiles/<Агент>/memory/stabledif_out/<TS>_seed<seed>.png
- Лог: profiles/<Агент>/memory/stabledif.log

Кому что видно: агент vs оператор
---------------------------------

Три слоя вывода, и на каждом — свой язык.

| Слой | Кому | Что пишем |
| Докстринг команды, имена параметров, справка, ошибки команд | агенту | только «контекст». Слова «буфер» нет. Параметр — в_контекст. |
| Return-сообщения ([BUF] ...) | оператору | «буфер обмена» — как есть. Оператор видит консоль, ему нужно знать, что попало в Ctrl+V. |
| Маркер [BUF] в начале строки | обоим | технический тег для cmd_parser. Не переводим, не убираем. |

Почему так. Агент живёт в тексте: он видит вывод команды и передаёт его
дальше. Для него «буфер обмена» — чужая абстракция: у него нет глаз, чтобы
посмотреть, что там лежит. Ему нужно понимать только одно: эти данные попадут
в контекст следующего шага (то, чем система ответит агенту). Поэтому в
докстрингах и параметрах — в_контекст, а не в_буфер.

Оператор — за консолью. Ему, наоборот, полезно видеть «буфер обмена», потому
что он нажимает Ctrl+V в проводнике / Word / Photoshop. `[BUF] Картинка в
буфере обмена` — точное описание того, что произошло.

Практика.

- Меняешь докстринг — пиши «контекст».
- Меняешь return — пиши «буфер обмена».
- Меняешь параметр — в_контекст (старое в_буфер работает как алиас для
  совместимости, но в докстрингах не светится).

Пример правильного:

@register("показать_картинку")
def show_image(args):
    """Показать картинку.

    Параметры:
      путь — путь к изображению (обязательно)
      в_контекст — положить в контекст (по умолч. true)
    """
    ...
    if to_ctx:
        clipboard.set(img)
        return "[BUF] Картинка в буфере обмена"

Агент видит: «есть параметр в_контекст». Оператор видит: `[BUF] Картинка в
буфере обмена`.

• Tor — для Moltbook и Tavily. Есть тор_запрос — всегда через Tor.
• Hot-reload — _actions/*.py и часть _core/* подхватываются на лету.
• Heredoc — для длинных текстов. >>> сам выполняет.
• UNaIVERSE agent-to-agent — не работает (их баг).
• Никаких хардкод-путей. Все пути — от BASE_DIR, side/config.json или env-var. anyjson работает из любой папки: переместил — и всё живо.
• Общие эталоны — data/etalons/. Для видео и аудио — один
   набор (speech + tembr). Ищется вверх по дереву от __file__,
   без хардкода.
• UAC — не проблема. Windows-запросы на подтверждение (UAC) — норма. Forge, zapret, симулятор и другие процессы, которые требуют повышенных прав, запускаются через ShellExecuteW(..., 'runas', ...) — Windows покажет окно подтверждения. Не считать это ошибкой и не пытаться обходить. Оператор подтвердит.

• Агент не знает про буфер. В докстрингах и параметрах команд не должно быть слова «буфер» — ни в_буфер, ни «кладётся в буфер», ни «посмотри картинку». Агент получает результат как обычный текст.
    Оператор видит буфер по маркеру [BUF] 📋 ... в консоли. Это часть вывода для человека, не для агента.
    В _extract_params_ast подстрока буфер входит в стоп-слова (BAD), поэтому параметр в_буфер не всплывает в подсказках.

• IPv4-only резолв. _config.py переопределяет
    socket.getaddrinfo — только AF_INET. Это убирает ошибки
    getaddrinfo failed, когда локальный DNS отдаёт IPv6 первым,
    а IPv6 в сети не работает.

Тесты и диагностика
-------------------

Формализованного test-runner'а нет. Всё делается ad-hoc скриптами в side/.

Валидатор импортов

Запускается автоматически при старте anyjson.py. Проверяет все _actions/*.py на битые импорты. Если что-то не так — REPL не стартует, sys.exit(3). Отдельно запускать не нужно.

Проверить, что реестр команд в порядке

Создай side\_check.py:

import sys
sys.argv = ["_check.py", "Ассистент"]
sys.path.insert(0, r"E:\Jericho\Private\anyjson")
sys.path.insert(0, r"E:\Jericho\Private\anyjson\_core")
from _actions import HANDLERS, PRIMARY_HANDLERS, load_all
load_all()
print("HANDLERS:", len(HANDLERS), "PRIMARY:", len(PRIMARY_HANDLERS))

Запусти:

python E:\Jericho\Private\anyjson\side\_check.py
Remove-Item E:\Jericho\Private\anyjson\side\_check.py

Проверить синтаксис _actions/foo.py

python -c "import ast,pathlib; ast.parse(pathlib.Path(r'E:\Jericho\Private\anyjson\_actions\foo.py').read_text(encoding='utf-8'))"

Правила для скрипта-проверки

• Имя агента — в sys.argv до импорта _config:
   sys.argv = ["_check.py", "Ассистент"]
   Иначе _ask_name() уйдёт в input() — зависнет или EOFError.

• sys.path — добавить anyjson/ и anyjson/_core/:
   sys.path.insert(0, r"E:\Jericho\Private\anyjson")
   sys.path.insert(0, r"E:\Jericho\Private\anyjson\_core")

• Скрипт — в side/, удаляется сразу. Никаких tests/ и pytest — так решено.

• load_all() в чистой сессии читает файлы с диска. Hot-reload действует только в REPL anyjson.

Режим работы: через PowerShell
------------------------------

Окружение: PowerShell 7.6.6. utf8NoBOM есть, @(...) работает. PS 5.1 не используем — там нет -Encoding utf8NoBOM, а многострочная вставка в консоль рвётся с ParserError.

anyjson правится PS-командами, а не «сохрани файл в редакторе».

Разовый код — py -c

py -c "print(1+1)"

Многострочно — PS here-string @" ... "@

py -c @"
import sys
print(sys.version)
"@

Правила: @" и "@ — на своей строке, "@ в самом начале, отступов нет.

Осторожно: @" ... "@ подставляет $переменные. Если в Python-коде есть $ — бери @' ... '@ или массив строк.

Патч файла — массив single-quoted строк

Главное правило: если в патче есть markdown-с-бэктиками или много ',
используй массив @('...', '...'), а не @'...'@.

$lines = @(
    'import pathlib',
    'p = pathlib.Path(r"E:\Jericho\Private\anyjson\Readme.txt")',
    'print(p.read_text(encoding="utf-8")[:200])',
)
$src = $lines -join "`r`n"
Set-Content E:\Jericho\Private\anyjson\side\_patch.py -Value $src -Encoding utf8NoBOM
python E:\Jericho\Private\anyjson\side\_patch.py
Remove-Item E:\Jericho\Private\anyjson\side\_patch.py

Markdown с бэктиками

@'...'@ (одиночный here-string) рвётся на длинном тексте с бэктиками и '.
Два надёжных способа:

• Массив строк @('...', '...') — каждая строка парсится независимо,
   ' экранируется как '', всё остальное (` , #, $, @) — литерал.
• ~~~ вместо ``` — тильда в PS не имеет спецсмысла вообще.

Работа с файлами — проси полный путь

Главное правило сессии. Если нужно посмотреть содержимое файла — не проси py-скрипт,
не проси «покажи первые N строк», не режь на куски. Просто скажи: «дай полный путь».
Пользователь вставит содержимое целиком, одним сообщением.

Плохо:

Скинь py-команду, которая прочитает первые 100 строк C:\temp\big.svg

Хорошо:

Дай полный путь к big.svg — я открою целиком.

Это правило перебивает любые другие: даже если файл большой, «кусочный» вывод
через py -c, head, Select-Object -First N — не предлагать. Пользователь сам
решит, сколько показать.

Кавычки в PS-массиве — главная ловушка

Внутри @('...', '...') каждая строка закрывается на первой '. Если внутри
строки есть ' (а в Python-коде они повсюду) — PS сломается на
ParserError: Непредвиденный токен.

Правило: каждую одиночную ' внутри '...' писать как '' (две).
Так работает любой PS.

$lines = @(
    'print("hi")',
    's = ''it''''s ok''',        # в Python: s = ''it''''s ok''
    'from _actions import register',
)

Второй способ — вообще избежать кавычек: в Python-коде писать только ",
а одиночных ' не иметь. Тогда PS-массив не требует экранирования. Так
делались все патчи этой сессии, кроме того, где я забыл.

$lines = @(
    'print("hi")',              # в Python: print("hi")
    's = "it''s ok"',            # в Python: s = "it''s ok" — PS: '' -> '
)

Если в строке много ' — бери @'...'@ (single-quoted here-string),
а не массив. Внутри него ничего не экранируется.

Если и в @'...'@ сложно — вынеси Python-скрипт в side\_patch.py
через базовый [IO.File]::WriteAllText и @'...'@ — самый устойчивый путь.

Как править Readme.txt (и другие .txt) — без regex

Readme — просто текстовый файл. Не .py, не под hot-reload. Правится
pathlib.Path.write_text(), но с оговорками.

Главное правило: никаких re.sub по всему файлу.

В .md живут примеры — с бэкслэшами, кавычками, $, бэктиками. Они должны
остаться как есть. Жадный регексп их съест. Один раз так сломали таблицу про
экранирование бэкслэшей — все двойные бэкслэши в примерах стали одиночными,
смысл потерялся.

Правильно — точечный str.replace(old, new, 1) с уникальным контекстом.

Порядок:

• Новые большие секции — сначала в side/_new_sections.md через
   [IO.File]::WriteAllText и @'...'@ (single-quoted here-string,
   без подстановок).
• Патч-скрипт в side/ (Python): читает Readme, вставляет по маркеру.
• В патче — только s.replace(old, new, 1) с точной строкой (включая
   отступы, символы). Никаких re.sub.
• Если якорь не найден — print("ERROR: marker not found") и не
   продолжать. Скинуть контент пользователю, найти реальную строку.
• После — проверить s.count(marker) и что новые секции есть.
• Удалить временные файлы.

Проверка после патча:

py -c "import pathlib; p=pathlib.Path('E:/Jericho/Private/anyjson/Readme.txt'); s=p.read_text(encoding='utf-8'); print('ok:', 'Кому что видно' in s)"

Если replaced: 0 — не переходить к следующему шагу. Regex и «на глаз» тут
не спасут: в .md полно мест, где бэкслэш, кавычка, доллар, бэктик —
литералы, а не синтаксис. Их нельзя ни трогать, ни экранировать.

Ещё правило — не плодить нумерацию. Пункты внутри одной секции должны
идти подряд, без «11, 11, 12». Если вставил новый пункт — переномер остальные.
Патч через new_block = '''...''' — двойной escape

Если пишешь патч-скрипт, который сам содержит Python-код для вставки
в целевой файл — используй двойной escape для \n, \t, \\.

Что происходит. PowerShell here-string @'...'@ передаёт текст
буквально. Но Python-парсер патч-скрипта видит new_block = '''...'''
и интерпретирует \n внутри как реальную новую строку. То есть
в new_block попадает не два символа \ n, а один перенос строки.

Когда патч пишет new_block в целевой файл — там оказывается
живой перенос внутри строкового литерала:

return "
".join(lines)     # ← SyntaxError: unterminated string literal

Правило. Если в целевом файле нужно, чтобы было "\n".join(...) —
пиши в патче "\\n".join(...). То же для \t, \\, \xNN, \uXXXX.

| Что нужно в файле | Что писать в патче |
| "\n" | "\\n" |
| "\t" | "\\t" |
| "\\" | "\\\\" |
| "\x41" | "\\x41" |

Альтернатива — не писать \n вообще. Использовать chr(10):

return chr(10).join(lines)

Это надёжнее: chr(10) не содержит бэкслэшей, PS-here-string не тронет,
Python-парсер патча не тронет, в файл попадёт как есть.

Если патч уже сломал файл — проверить синтаксис ast.parse(...)
до hot-reload. Ошибка видна сразу:

py -c "import ast,pathlib; ast.parse(pathlib.Path('E:/Jericho/Private/anyjson/_actions/foo.py').read_text(encoding='utf-8')); print('OK')"
Экранирование бэкслэшей

Правило: в PS-строке \ — это литерал, а не escape-символ. Escape-символ в PS — бэктик (`). Значит, в массиве @('...', '...') пиши ровно то, что хочешь видеть в .py-файле. Ничего не удваивай "для PS".

Цель в .py-файле              | Как писать в PS-массиве @('...', '...')
------------------------------|-----------------------------------------
p = Path(r"C:\temp")          | 'p = Path(r"C:\temp")'
s = "C:\\temp"                 | 's = "C:\\temp"'
re.sub(r"\\", "/", s)          | 're.sub(r"\\", "/", s)'
print("a\nb")                 | 'print("a\nb")'

В PS одинарные кавычки не трогают \ вообще. Но бэктик внутри '...' остаётся литералом — если надо передать `, пиши его как есть.

Плохие ловушки:

Что написал в PS-массив         | Что оказалось в .py-файле     | Что видит Python
--------------------------------|-------------------------------|------------------
's = "C:\temp"'                | s = "C:\temp"                | C:<TAB>emp
                                |                               | (\t = tab!)
's = "C:\\temp"'              | s = "C:\\temp"              | C:\temp  (правильно)

Если бэкслэшей много — избегай их вообще:

- Пути — через прямой слэш: Path("C:/temp") работает и на Windows.
- Нужен литеральный \ в Python-строке — пиши chr(92). PS-массив не трогает chr(92), Python получает ровно \.

# Плохо — четыре бэкслэша, считать в голове:
$lines = @('    s = s.replace("\\\\", "/")')

# Хорошо — однозначно:
$lines = @('    s = s.replace(chr(92), "/")')

Запуск anyjson из скрипта

Имя агента — обязательно первым аргументом. Без него _ask_name() уйдёт в
input() — в subprocess это зависание или EOFError.

py E:\Jericho\Private\anyjson\anyjson.py Художник
py E:\Jericho\Private\anyjson\anyjson.py Мой Агент

Из Python:

import subprocess
subprocess.run(["py", r"E:\Jericho\Private\anyjson\anyjson.py", "Художник"], check=False)

Одноразовая команда без входа в REPL:

'{"эхо": {"текст": "hi"}}' | py E:\Jericho\Private\anyjson\anyjson.py Художник

Договор

• Кодировка — -Encoding utf8NoBOM (PS 7+).
• Временные скрипты — в side\, удаляются сразу.
• anyjson.py — не hot-reload, перезапуск. _actions/*.py — reload сами.
• Markdown — через массив строк или ~~~, не через @'...'@.
• Python-патчи пиши без одинарных кавычек (только "), тогда PS-массив не требует экранирования.
• @"..."@ в PS подставляет $переменные — если в коде есть $, бери @'...'@.
• Не проси читать куски. Проси полный путь — пользователь пришлёт файл целиком.
• ' внутри PS-массива → ''. В @('...', '...') любая ' внутри
   строки должна быть ''. Если так лень считать — пиши Python-код без
   одинарных кавычек, только ". Для длинных патчей — @'...'@
   через [IO.File]::WriteAllText.

• Никаких хардкод-путей. anyjson должен работать из любой папки — переместил и всё живо.
   - В Python — от BASE_DIR (в _config.py, вычисляется из __file__).
   - В конфиге — side/config.json относительными путями, resolve_path() раскрывает их от BASE_DIR.
   - Для внешних скриптов (тех, что лежат вне anyjson) — через env-var, например ANYJSON_ETALONS_DIR.
   - Никаких r"E:\Jericho\..." и "C:/temp" в коде. Только в докстрингах/примерах.

• Спорит — значит не применял. Если пользователь обсуждает патч,
    возражает, предлагает другой вариант — патч не выполнен. Прежде чем
    предлагать следующий шаг, проверь текущее состояние файла (grep, чтение
    строк), не полагайся на «уже должно быть применено».
