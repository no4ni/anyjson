anyjson
=======

Инструмент, которым внешний LLM (DeepSeek, GPT и т.п.) пользуется через JSON-команды.
Пользователь вводит JSON в консоль anyjson — команды выполняются. Обратной связи
«LLM внутри anyjson» нет, LLM снаружи.

---

Кто читает этот файл
--------------------

Ты — не агент anyjson. Ты помощник разработки anyjson: внешний
LLM, который помогает оператору править код, докстринги,
структуру, патчи.

Ты — не пользователь anyjson. Пользователь — оператор.
Ты не вводишь JSON-команды в REPL anyjson, не запускаешь
anyjson и не работаешь с его консолью. Ты формулируешь
команду или патч текстом — оператор выполняет их сам.
Слово «пользователь» в этом файле всегда означает оператора,
а не тебя.

Прямого доступа к файловой системе у тебя нет: ты не выполняешь
команды, не читаешь и не пишешь файлы сам. Ты видишь только
то, что оператор вставил в чат, и влияешь только на то, что
оператор запустил.

**Readme — твоя ответственность.** Следи, чтобы он оставался
актуальным и не превышал 100 КБ. Когда добавляешь команду, меняешь
поведение, узнаёшь новую граблю — сразу давай оператору команду
обновить Readme. Не спрашивай «дописать?» — просто отдавай команду
через заменить_текст / переписать. Следи за размером через
список_файлов; если > 100 КБ, вырезай устаревшее (или через
подсказать_сокращения, но помни: для технической документации
T5 врёт, ручная редактура надёжнее).

Доступ — косвенный, через оператора. Ты даёшь команды и патчи,
оператор их выполняет. Ты называешь путь — оператор отдаёт
содержимое.

Поэтому: чтобы получить файл, назови ПОЛНЫЙ путь. Не «открой
_ps.py», а:

    E:\Jericho\Private\anyjson\_core\_ps.py

Оператор сам решит, как отдать содержимое: скопирует из
редактора, прогонит через {"читать_по_кб": {"путь": "..."}}
или {"прочитать_полностью": {"путь": "..."}}.

Патчи — тоже с полного пути. «Патчим _ps.py» — плохо.
«Патчим E:\Jericho\Private\anyjson\_core\_ps.py» — хорошо.

Запрашивай файлы целиком, не фрагментами. «Покажи строки 250-330»
теряет контекст (импорты, соседние функции, отступы), и через
итерацию всё равно придётся просить ещё кусок. Один полный файл
читается быстрее, чем пять точечных запросов. Исключение —
гигантский файл (тысячи строк): тогда конкретную функцию
по имени через прочитать_функцию.

---

Патчи: правила работы

Правило первое. Многострочный текст в PS-консоль — через
here-string:

  $insert = @'
  строка
  строка
  '@

Не через @(...) -join: при вставке из буфера в консоль массив
может схлопнуться в пустую строку, Replace() молча удалит
якорь, файл останется без вставки. Это уже случалось.

Правило второе. Не выдумывай пути. Если полного пути нет —
скажи оператору, какой файл нужен, попроси найти
(найти_файл / найти_всё / список_файлов). Файлы вида
_tools_X.py, которых нет, — типичная галлюцинация.

Правило третье. Патч любого *.py — только с бэкапом:

  {"создать_бэкап": {"путь": "E:/путь/к/файлу.py"}}

Создаёт <путь>.bak_YYYYMMDD_HHMMSS рядом с файлом (или в в_папку).
Формат имени совпадает с удалить_старые_бэкапы — старые копии
потом чистятся штатно.

Readme.txt патчится тем же способом. README не hot-reload,
после правки — просто перезаписать и всё.

Правило четвёртое. Якоря для Replace — уникальные. Перед заменой
проверяй Count вхождений:

  ([regex]::Matches($txt, [regex]::Escape($anchor))).Count

Если больше одного — уточни якорь, иначе патч ударит не туда.

Правило пятое. Независимые патчи — одной |||-цепочкой, в одном блоке.

Если несколько заменить_текст / заменить_функцию не зависят друг от
друга (разные якоря, один патч не ломает якорь другого) — отдавай
их одной |||-цепочкой в ОДНОМ блоке ```json. Несколько отдельных
блоков в одном ответе — плохо: оператор копирует первый, выполняет,
и до остальных может не дойти (или потратит время на поштучное
копирование). Это уже случалось.

ВАЖНО: ||| ставится на ТОЙ ЖЕ строке, что закрывающие фигурные
скобки команды. Никаких переводов строки перед |||. Если поставить
||| первым символом новой строки — цепочка распадётся, выполнится
только последний блок (или anyjson вообще не разберёт ввод).
Проверено на convert.py: два патча из трёх потерялись именно из-за
перевода строки перед |||.

Зависимые патчи — только по одному, по порядку. Классический случай:
один заменить_текст вставляет строку, второй патч её же (или
якорь рядом) использует.

Правило шестое. anyjson не запускается — только PowerShell.
Если anyjson не стартует (валидатор, SyntaxError, guard), JSON-команды
бесполезны: их некому выполнять. Правки — через PS here-string
с проверкой якоря и бэкапом. Скрипт-образец — в истории сессий
(ReadAllBytes → GetString → Replace → py -m py_compile → WriteAllBytes).

Правило седьмое. В теле heredoc-патча не должно быть литералов
<<< и >>>.
Они закроют блок раньше времени (или откроют новый). Если в тексте
патча нужно слово «subprocessprocess» или сам маркер — собирай через
конкатенацию: "sub"+"process", chr(60)*3, chr(62)*3. Так guard
не сработает и heredoc не оборвётся.

Правило восьмое. Отступы в якорях — точные.
В Python отступ = 4 пробела, но в разных функциях он разный
(метод класса — 8, вложенный блок — 12). Копируй якорь из вывода
«ближайшие совпадения» — там видно точное число пробелов.
Перед записью всегда предпросмотр: true; если в diff стоит
+r = ... без отступа — стоп, якорь/замена съехали.

---

Имя агента

Имя задаётся первым аргументом командной строки:

py anyjson.py Ассистент
py anyjson.py "Мой Агент"

Несколько аргументов склеиваются через пробел:

py anyjson.py Мой Агент      # то же, что "Мой Агент"

Без аргументов anyjson спросит имя интерактивно (_ask_name(), input("> ")).
В скрипте / subprocess / CI так нельзя — зависнет или упадёт с EOFError.
Всегда передавай имя первым аргументом.

Перед _sanitize_name имя проходит _extract_name: если есть
продолжение после первой . ! ? ; :, — хвост срезается.
«SAAI. Готов к работе.» → SAAI, «SAAI.» → SAAI. Также
понимает «Имя: X», «**X**», «меня зовут X», «My name is X».

Из имени вычищаются < > : " / \ | ? *, скобки, кавычки, запятые и управляющие
символы (_sanitize_name). Пробелы и дефисы остаются. Результат — имя папки
profiles\<Агент>\memory\.

Файл side\config.json обязателен — без него _config.py делает sys.exit(1)
с сообщением «Караул! Скрижаль Конфигурации утеряна».

Формат ввода
------------

Одна команда:

{"имя_команды": {"параметр": "значение"}}

Несколько команд в одной строке — через |||:

{"эхо": {"текст": "hi"}}|||{"время": {}}

Если в буфере остался открытый {/[ или открытый <<< без >>>,
строка с ||| не выполняется сразу — копится, как обычный многострочный
JSON, до баланса скобок и закрытия heredoc. Так работает:

  {"a": {}}|||{"b": {"текст": <<<
  многострочно
  >>>}}

Раньше такой ввод обрывался на первой строке (баг исправлен).

Если несколько JSON-команд введены подряд (каждая с новой строки,
без |||) — anyjson обнаружит их, выполнит последовательно и добавит
в результаты уведомление:

   ℹ️ Выполнено N команд последовательно.
      Параллельно: {"параллельно": [ ... ]}
      Отключить это уведомление: разделяйте команды через |||.

Многострочный JSON — копится в буфере. REPL ждёт, пока не закроются
все открытые { и [ (скобки считаются вне кавычек — { внутри строк
не мешает). Как только баланс сошёлся — выполняет сразу, без пустых
строк.

Одна пустая строка — принудительное выполнение, если по какой-то
причине баланс не сошёлся. Две — для ввода, не начинающегося с {.

Heredoc — для длинных текстов и кода

Все команды с телом принимают его через inline-heredoc — значение
поля оборачивается в <<< ... >>> прямо в JSON, без экранирования.
Примеры ниже.

Inline-heredoc (внутри JSON, для любой команды)

В любом строковом параметре любой команды можно писать <<<...>>>
прямо внутри JSON — значение подставится как строка, без экранирования.
Один ведущий и один хвостовой \n обрезаются; литерал >>> внутри
тела закроет блок раньше времени. ||| внутри <<<...>>> — часть тела,
а не разделитель команд: сплиттер не режет по |||, пока не закрыт >>>.
То же с кавычками внутри тела — не интерпретируются.

  {"заменить_текст": {"путь": "a.txt", "найти": <<<
  старый
  текст
  >>>, "заменить": <<<
  новый
  текст
  >>>}}

Работает для любой команды с текстовым параметром:
заменить_текст, заменить_функцию, переписать, добавить, питон и др.

Многострочный код для «питон»:

  {"питон": {"скрипт": <<<
  import json
  print(json.dumps({"a": 1}))
  >>>}}

Внутри <<<...>>> не оставляй 3 пустые строки подряд.

Автопочин незакрытых скобок в JSON

Если JSON не разобран, скобки несбалансированы (не хватает } или ]),
и мы не внутри строки — anyjson дописывает недостающие в конец и
выполняет повторно. В результатах появляется предупреждение без
номера — до списка выполненных команд:

  {"запомнить": {"содержимое": "текст"}

  Результаты:
     ⚠️ JSON не закрыт — автопочин добавил: } (возможно, забыл закрыть в конце?)
  1. Запомнил: текст

Если автопочин не помог — в ответе позиция ошибки, фрагмент вокруг
неё и счётчик незакрытых скобок. Запятые «на глаз» не подставляются:
если пропущена запятая между парами — обычная ошибка, без автопочина.

Shell-питон

Ввод вида `python girls.py "arg1" "arg2"` anyjson не выполняет.
Вместо этого — «❌ Не понял ввод» с готовым JSON-шаблоном для
команды «питон»:

  💡 Похоже на запуск Python из консоли. В anyjson для этого есть
  команда «питон»:
  {"питон": {"скрипт": "girls.py", "аргументы": ["arg1", "arg2"]}}

Аргументы парсятся через shlex, кавычки снимаются.

Регистрация команд
------------------

from _actions import register

@register(["читать", "прочитать", "прочитай"])
def read_(args: dict) -> str:
    ...
    return "ответ"

HANDLERS[name] = func — для каждого имени.

HANDLERS и PRIMARY_HANDLERS

HANDLERS хранит все имена команд, включая алиасы (читай, прочти, шелл, stop).
PRIMARY_HANDLERS хранит только первое имя из каждого @register(...) — канонический вариант.

- Все алиасы работают — разницы для вызова нет.
- Подсказки (пакетный режим, случайные примеры, «Ты пробовал(а) команду X?»)
  берутся из PRIMARY_HANDLERS, чтобы не мелькали алиасы.

Пример:

@register(["запуск", "терминал", "шелл"])

- HANDLERS: запуск, терминал, шелл — три записи, все ведут на одну функцию.
- PRIMARY_HANDLERS: только запуск.

Правило имён

Все имена команд — только на кириллице (плюс цифры и _).
Любая латиница в имени команды блокируется с подсказкой русского аналога:

❌ Команда "echo" — латинский алиас, используй русское имя:
  • "эхо"

Если латинское имя зарегистрировано, но у него есть кириллический брат-близнец —
подсказка покажет русское имя. Если нет — общая подсказка
❌ Название команды должно быть на русском, например: ....

Правки файлов (для LLM)
-----------------------

Инструменты точечных правок кода, докстрингов, конфигов.

- переписать — записать файл целиком. Параметры: путь, содержание
  (алиас содержимое). Без предпросмотра/нестрогого — пишет сразу;
  для безопасной правки — заменить_текст/заменить_функцию.
  Многострочный текст — heredoc (маркеры из трёх угловых скобок,
  см. «Формат ввода»); сами маркеры в теле патча не пиши.
- добавить — дописать в конец. Параметры: путь, содержание.
- заменить_текст — X → Y в файле. Параметры: путь, найти, заменить,
  все, регистр, регулярка, предпросмотр, нестрого, показать_близкое.
  • нестрого (по умолч. true) — нормализует NBSP, тире, «», 2+ пустых,
    CRLF↔LF; при срабатывании пишет НОРМАЛИЗОВАННЫЙ текст (может
    затронуть больше, чем место замены). Для точной строки — false.
  • регулярка: true — find как regex; точка не матчит \n, блок — через
    [\s\S]*? (напр. «НАЧАЛО[\s\S]*?(?=КОНЕЦ)»).
  • предпросмотр: true — diff и счётчик, файл не писать.
  • показать_близкое (по умолч. true) — при replaced: 0 вывод начинается
    с «🔍 Первое расхождение» (строка, направление, repr лишнего);
    ближайшие строки с repr; без «сходства в %».
- заменить_функцию — заменить функцию по имени. Параметры: имя, путь,
  содержание. Бэкап + AST-проверка, сломанный код откатывается.
- найти_функцию — AST-поиск def в исходниках. Параметры: имя
  (подстрока или regex), регулярка, точно, тело, путь (_actions +
  _core + anyjson.py), количество. Показывает файл:строку; с
  телом: true — исходник. Удобно, когда не знаешь, где живёт функция.
- прочитать_функцию — прочитать одну функцию по имени (AST).
  Параметры: имя, путь (без пути — все _actions/*.py).
- проверить_синтаксис — проверить .py или строку без выполнения.
  Параметры: путь или скрипт.
- осмотреть — поиск по содержимому. Параметры: путь, ключевые_слова,
  количество, вокруг, регулярка (иначе подстрока). Через side/inspect.ps1.
- создать_бэкап — копия файла <путь>.bak_YYYYMMDD_HHMMSS.
  Параметры: путь, в_папку (алиас куда), суффикс. Формат имени
  совместим с удалить_старые_бэкапы. Папки не бэкапятся.
- удалить_старые_бэкапы — чистка *.bak*. Параметры: папка (алиас путь),
  старше_дней (7), безопасно. Для каждого базового X: есть свежие —
  старые удаляются; все старые — остаётся самый новый. Timestamp из
  имени (X.bak_TS / X_TS.bak / X.bakTS) или mtime. безопасно: true —
  только предпросмотр.
- дедуплицировать_строки — удалить повторяющиеся строки.
  Алиасы: убрать_дубли_строк, dedupe_lines. Параметры: путь (алиас файл),
  сохранить (алиас выход; по умолч. перезапись), подряд (true — только
  подряд; false — все дубли с первым вхождением), пустые (false — не
  считать дублями), пробелы (true — после strip()), нестрого
  (нормализация NBSP/кавычек/тире), предпросмотр (только показать),
  перезаписать (разрешить запись в существующий «сохранить»).
  Кодировку и CRLF/LF сохраняет. Возврат: «Удалено N строк (было X,
  стало Y)». Для кода осторожно: две подряд «pass»/«return None»
  могут быть осмысленны — предпросмотр: true.

Подсказка при ошибке

AssertionError в патч-скрипте — якорь не найден. Для точечных правок
удобнее заменить_текст (предпросмотр, нестрогий, регулярка). Если
assert упал на якоре — не перебирай якоря через питон.

Hot-reload
----------

Правки в файлах подхватываются на лету при следующей команде:

| Файл | Поведение |
| _actions/*.py | ✅ reload |
| _core/_utils.py | ✅ reload |
| _core/_color.py | ✅ reload |
| _core/_executor.py | ✅ reload |
| _core/_ps.py | ✅ reload, _ps_cwd сохраняется |
| _core/_config.py | ⚠️ предупреждение, нужен перезапуск |
| _core/_storage.py | ⚠️ перезапуск |
| _core/_tor.py | ⚠️ перезапуск |
| _core/_safe_subprocess.py | ⚠️ перезапуск |
| _core/_web.py | ⚠️ перезапуск |
| _core/_py_guard.py | ✅ подхват сразу, без warn (_CORE_SILENT) |
| anyjson.py | ❌ не отслеживается |

Правило: не делай from X import y в anyjson.py

reload переисполняет код в том же объекте модуля, но не трогает
локальные ссылки, скопированные через from X import y. То есть:

- import _actions.cmd_parser as _cmd_parser → reload работает,
  потому что _cmd_parser.process_command_input резолвится в момент вызова.
- from _actions.cmd_parser import process_command_input → reload не работает,
  потому что process_command_input — это старая ссылка на функцию.

Правило: в anyjson.py (и в _core/*.py, которые он импортирует)
всегда import X + X.foo(), а не from X import foo.

Пример: _cmd_parser.process_command_input(...) вместо
process_command_input(...).

Фильтры безопасности
--------------------

Страж subprocess (_core/_safe_subprocess.py)

Любой .py можно запустить только внутри BASE_DIR.
Исключение — контекст allow_external_py(), который выставляет только
команда «питон».

- Чужой .py → ExternalPyBlocked.
- python -c "..." (inline) → пропускается.
- python -m module → пропускается.
- Не-питоновые команды (ffmpeg, curl, cleanmgr, ...) → не трогает.

Покрытие (с 24.09.2026):

- subprocess.run / Popen / call / check_output / check_call
- os.system
- os.popen
- shell=True со строкой: "python x.py", "echo hi && python x.py"
- имена python, python3, python3.11, python.exe, py, pyw — распознаются

Запрет записи

{"переписать"} и {"добавить"} запрещают запись в:

- C:\Windows
- C:\Program Files
- C:\Program Files (x86)
- C:\ProgramData

Ограничения {"питон"}

Regex-блок по тексту скрипта (быстрый отказ до запуска процесса):
os.system, subprocess, eval, exec, socket, requests, shutil.rmtree.

Плюс audit hook (_core/_py_guard.py). Команда «питон» запускает
скрипт не напрямую, а через guard, который ставит sys.addaudithook
и блокирует:

- запись (open на w/a/x/+), удаление, переименование и rmtree
  в системных папках (C:\Windows, C:\Program Files, C:\ProgramData,
  C:\$Recycle.Bin, C:\Recovery, C:\Boot и т.п.);
- любые os.system, os.exec;
- subprocess.Popen — за исключением ffmpeg/ffprobe из доверенных
  каталогов: dirname(config.paths.ffmpeg_exe / ffprobe_exe),
  site-packages, бандл imageio-ffmpeg. argv с shell-метасимволами
  (& | ; < > ( )) и shell=True блокируются всегда. В сообщении о
  блоке видно имя бинаря (например, subprocess.Popen (notepad.exe));
- любой shutil.rmtree — независимо от пути.

Нарушение → одна строка в stderr + os._exit(3), без traceback
и без утечки имени guard-файла. os._exit не ловится try/except,
скрипт умирает, даже если попытается проглотить ошибку.

Режим в_файл (только у {"питон"}):

- вывод скрипта идёт в указанный файл, в контекст — короткая сводка;
- если скрипт упал сам (SyntaxError, IndentationError, Traceback,
  non-zero exit) — файл НЕ создаётся, вывод идёт в контекст как у
  обычного «питон»;
- если вывод меньше 1 КБ — в сводке подсказка, что «в_файл» тут
  избыточен.

Guard не только блокирует, но и даёт подсказки — куда идти вместо
запрещённого вызова:

- shutil.rmtree → удалить_папку / удалить_путь / удалить_пустые_папки
  / убраться_в
- os.system / subprocess.Popen / os.exec → {"запуск": {"команда": ...}}
  или вложенный {"питон": {"скрипт": "..."}}
- запись в защищённую папку → переписать / добавить
- удаление/переименование в защищённой папке → удалить_файл / переместить

Зачем hook поверх regex: regex ловит «os.system» текстом и обходится
через «from os import system», «importlib», «getattr». Hook ловит
событие на уровне интерпретатора и не обходится. Regex остаётся
как быстрый слой (не тратить время на старт Python ради отказа).

leak_guard

Блокирует отправку во внешние сервисы (Moltbook, UNaIVERSE) текста с секретами:

- password, passwd, pwd, passphrase,
- api_key, apikey,
- private_key, secret_key,
- token, secret, bearer, authorization,
- форматы: sk-..., xoxb-..., ghp_..., Bearer ..., длинные hex (40+).

Маскировка вывода (mask_secrets)

tools_leak_guard.mask_secrets() вызывается в cmd_parser._mask() и _ps._mask()
— любой вывод команды, до печати и до копирования в буфер.

Заменяет на *:

- email (любой),
- sk-..., xoxb-..., ghp_..., Bearer ...,
- длинные base64url-строки (≥40 символов, не чистый hex, ≥3 категории из
  {верхний, нижний, цифры, -/_}).

Это маскировка вывода, не блокировка. leak_guard блокирует отправку,
mask_secrets — маскирует в показе.

Email маскируется в выводе, но при отправке во внешние сервисы не блокируется
— это идентификатор, не секрет.

Tor
---

- ControlPort 9051 — для ротации exit-нод (stem, NEWNYM).
- torrc — в конфиге (_TORRC). Добавлены:

ControlPort 9051
  CookieAuthentication 0
  MaxCircuitDirtiness 60
  NewCircuitPeriod 30

- new_circuit(wait_sec=2.0) — запросить новую exit-ноду.
- Retry в Moltbook — при CloudFront 403 и timeout (до 10 попыток с ротацией).
- Tavily — только через Tor (socks5h://127.0.0.1:9050). Напрямую из РФ → 403.
- DNS через Tor — везде socks5h://, а не socks5://. Это значит, что имя
  сайта резолвится на стороне Tor, а не локально. Спасает, когда локальный DNS
  отдаёт IPv6 первым или вообще падает.

тор_запрос — всегда через Tor

Алиас веб_запроса, но авто_прокси: true жёстко вшит. Параметр авто_прокси
игнорируется. Все остальные параметры (метод, заголовки, тело,
сохранить_как, таймаут, страница, размер, обновить) — как у веб_запрос.

{"тор_запрос": {"адрес": "http://check.torproject.org/", "таймаут": 30}}
{"тор_запрос": {"адрес": "http://www.insecam.org/en/bycountry/RU/", "таймаут": 120, "обновить": true}}
{"тор_запрос": {"адрес": "https://api.example.com/data", "метод": "POST",
                "тело": {"ключ": "значение"}, "таймаут": 60}}

Где использовать: Insecam, Cloudflare-домены, любые сайты, которые блокируют
российские IP, — а также когда локальный DNS сбоит, а через Tor всё работает.

Команды

НЕ поднимают демон: юнайверс_статус (проверка), юнайверс_лог

(подключиться, войти_в_мир, покинуть) показывают прогресс-бар.

Особенности

- Agent(HumanModule with explicit streams) — text-only.
  Не объявляем img-выход, иначе UNaIVERSE открывает камеру (cv2.VideoCapture(0)).
- asyncio.sleep ≥ 0.05s — их главный цикл вызывал sleep(0.001) и жёг ядро.
- prompt_toolkit.patch_stdout → no-op, prompt() → заглушка. Иначе падает
  на отсутствии консоли.
- stdin=DEVNULL у демона — чтобы не перехватывал REPL-ввод.
- NODE_IGNORE_ALIVE=1 — обход серверной блокировки имени (безопасно, потому
  что мы сами гарантируем отсутствие дублей через PID-файл и _kill_orphan_agents).
- Демон запускается с CREATE_NO_WINDOW, но при этом CREATE_NEW_PROCESS_GROUP.
- Файлы обмена (в MY_DIR): unaiverse_cmd.jsonl, unaiverse_result.jsonl,
  unaiverse_inbox.jsonl, human_input.txt, unaiverse.log, unaiverse.pid.

Ограничения UNaIVERSE: agent-to-agent P2P не работает (баг платформы).

.lotty (Lottie с текстурами)
-----------------------------

Три команды в _actions/lottie.py. Скрипты — в side/external/lottie/.

- текстурировать_лотти — наложить текстуры на слои .lotty.
  Параметр `текстуры` — строка формата:
    "ШАБЛОН:ТЕКСТУРА[:OP[:MODE]];..."
  Пример: "Корпус:metal.png:80:cover;Уши*:dark.png:85"
  OP — 0..100 (по умолч. 100), MODE — tile|stretch|cover (по умолч. tile).
  Путь к текстуре может быть абсолютным (C:/...).
  Несколько правил — через ';', хвостовой ';' допустим.

- конвертировать_лотти — SVG или HTML в .lotty.
  Параметры: вход, выход, ширина, высота.


- лотти_в_видео — .lotty в MP4 (или PNG-кадр при `кадр: true`).
  Параметры: вход, выход, fps, ширина, высота, масштаб, фон,
  качество, размытие, кадр, номер_кадра, отладка.

  Бюджет рендера фиксирован — 60 секунд. Рендерер сам решает,
  как уложиться (пользователь не может изменить):
    1. Изначальное W/H ≤ 1366×768 (пропорции сохраняются).
    2. После первого кадра — оценка полного времени. Если > 60с —
       снижает разрешение (time ∝ scale²), минимум 480p по меньшей
       стороне.
    3. Если на минимуме всё ещё > 60с — режет длительность (конец),
       floor 5 секунд (`Обрезка: 300 → 150 кадров`).
    4. При пропуске кадров (skip xN) fps пересчитывается:
       `fps 30 → 15 (skip x2)`, чтобы длительность совпадала.
    5. Маски масштабируются, кадры из предыдущих проходов
       переиспользуются из кэша (frame 0, frame 2 не рендерятся
       заново при resize/cut).
    6. W/H всегда чётные — libx264 не падает на `not divisible by 2`.

  В результате возвращаются ключевые строки: `Ограничение WxH`,
  `оценка на N кадров`, `⚠ Снижаю / Режу`, `Обрезка: A → B`,
  `fps X → Y`. Остальное (кадры, `[reuse]`, `Растеризация`) —
  только в консоли (стрим) или при `отладка: true`.

Подкапотные скрипты: apply_textures.py, svg2lottie_v6.py, render-lv6.py.
Запускаются через subprocess с PYTHONIOENCODING=utf-8 и
PYTHONUNBUFFERED=1 (см. _run_py — стримит вывод построчно).


Конвертация (универсальная)
---------------------------

Команда конвертировать / конвертация / перекодировать — единая точка
входа, маршрутизация по расширениям:

  видео↔видео (mkv/mp4/avi/mov/webm — перепаковка/перекодирование),
  видео→аудио (звук), видео→картинка (кадр на секунде, по умолч. 0),
  аудио↔аудио (mp3/wav/ogg/flac/aac/m4a/opus), аудио→картинка
  (спектрограмма), картинка↔картинка (png/jpg/webp/bmp/tiff),
  svg/html→.lotty, .lotty→.mp4, .lotty→.png (при «кадр»: true).

Параметры:

  путь              — вход (обязательно), алиас: файл
  сохранить         — куда. По умолч. рядом, расширение по цели:
                      video→.mp4, audio→.mp3, image→.jpg (из png) /
                      .png, svg/html→.lotty, lotty→.mp4 (или .png
                      при «кадр»: true)
  качество          — по ветке: видео — копия (по умолч.) / высокое
                      (CRF 18) / среднее (23) / низкое (28) / 0..51;
                      аудио — копия / высокое (320k) / среднее (192k) /
                      низкое (128k); картинки — высокое/среднее/низкое
                      или число (JPEG q); лотти — высокое/среднее/
                      низкое или CRF-число
  перезаписать      — false: не трогать существующий файл
  удалить_исходник  — false
  секунда           — только video→image: момент кадра (алиас время)
  ширина / высота   — audio→image (спектрограмма), svg/html→lotty
  кадр              — только .lotty: true — PNG вместо MP4
  fps, масштаб, фон, размытие, номер_кадра, кадры_маски,
  потоков_маски, кэш_альфы, кэш_текстур, масштаб_кадра, таймаут,
  отладка           — только .lotty→mp4/png, пробрасываются
                      в лотти_в_видео

Старые команды конвертировать_лотти, лотти_в_видео, кадр,
слушать_аудио/видео остаются — convert.py их вызывает.

Примеры:

  {"конвертировать": {"путь": "E:/video.mkv"}}
  {"конвертировать": {"путь": "E:/video.mkv",
                      "сохранить": "E:/out.mp4", "качество": "среднее"}}
  {"конвертировать": {"путь": "E:/video.mp4", "сохранить": "E:/audio.mp3"}}
  {"конвертировать": {"путь": "E:/video.mp4",
                      "сохранить": "E:/frame.png", "секунда": 12.5}}
  {"конвертировать": {"путь": "E:/art.lotty", "сохранить": "E:/art.mp4"}}

Заметки:

  • Видео→видео «копия» падает, если mp4 не принимает кодек
    (VP9/AV1/MPEG-2/DTS/AC3/FLAC/Vorbis) — «качество»: «среднее».
  • лотти→png: «кадр»: true принудительно меняет выход на .png
    даже при «сохранить»: «...mp4».
  • fps/масштаб/фон/... видны в «диагностике» — _extract_params_ast
    обходит сиблинги (convert_cmd → _convert_lotty_to_video),

Установка Python-пакетов (установить_пакет)
-------------------------------------------

Установка пакета из PyPI без выхода в PowerShell.

Параметры:
- имя      — имя пакета (обязательно), можно с extras;
- тихо     — true: без построчного вывода pip (по умолч. false);

- имя матчит regex ^[A-Za-z0-9][A-Za-z0-9_.\-]*(\[[A-Za-z0-9_,\-]+\])?$;

  --trusted-host, -e, file://, http://, https://, /, \, ;, &, |,
  >, <, $ и др.;
- вызов строго [sys.executable, "-m", "pip", "install", <имя>] —
  без shell, без дополнительных флагов, один пакет за раз.

Stable Diffusion (Forge)
------------------------

Генерация картинок через локальный Forge (форк A1111).

Путь и конфиг

В side/config.json:

{
  "paths": {
    "stabledif_dir": "E:/StableDif"
  }
}

В _config.py оттуда растут STABLEDIF_DIR, STABLEDIF_RUN,
STABLEDIF_HOST, STABLEDIF_PORT. Никаких хардкодов в *.py.

Запуск

Правильная цепочка — через run.bat (в корне StableDif):

  cd E:\StableDif
  run.bat

run.bat → environment.bat → webui\webui-user.bat.

environment.bat подсовывает встроенный Python
(E:\StableDif\system\python) и ставит SKIP_VENV=1.

webui-user.bat содержит нужные флаги:

set COMMANDLINE_ARGS=--api --server-name 127.0.0.1 --port 7860

- --api — REST API включён
- --server-name 127.0.0.1 — слушает только локально
- --port 7860

⛔ webui-user.bat НАПРЯМУЮ ЗАПУСКАТЬ НЕЛЬЗЯ.

Без environment.bat WebUI создаёт мусорный venv с системным
Python 3.13, пытается ставить torch==2.3.1 (его нет под 3.13),
падает на "Couldn't install torch". Если это случилось — удалить
E:\StableDif\webui\venv и запустить через run.bat.

В шапке webui-user.bat стоит предупреждение @REM об этом.

Из anyjson — Forge поднимается автоматически через STABLEDIF_RUN
(это E:\StableDif\run.bat). Прогресс старта: Forge стартует...
Ns ####. После первого запуска Forge остаётся в фоне — следующий
нарисуй мгновенный. При выходе anyjson Forge гасится (если
anyjson его поднял или взял шефство над уже работающим).

Если Forge уже работал до старта anyjson (запущен вручную),
anyjson записывает его PID в MY_DIR/stabledif.pid и всё равно
гасит при выходе. См. capture_forge_pid в stabledif.py.


Параметры нарисуй

- промпт — обязательно
- негатив
- ширина / высота — по умолчанию 512×512
- шаги — sampling steps, по умолчанию 20
- cfg — CFG Scale, по умолчанию 7.0
- seed — по умолчанию -1 (случайный)
- сэмплер — Euler a по умолчанию
- модель — имя чекпойнта, переключает на лету
- в_буфер — true по умолчанию
- сохранить — путь для PNG (иначе MY_DIR/stabledif_out/)

Пример:

{"нарисуй": {"промпт": "cat in a hat, oil painting",
             "негатив": "blurry, low quality",
             "ширина": 768, "высота": 768, "шаги": 30}}

Прогресс

Во время генерации — Осталось N сек. (обновляется в той же строке, не спамит).
ETA берётся из /sdapi/v1/progress.

SOLO_COMMANDS

стабилдиф, нарисуй, сгенерировать, txt2img, перерисуй, дорисуй,
убрать_фон, кроп, зеркало, слои, окно_в_мир, смотреть_видео,
посмотреть_картинку, прочитать_полностью и другие — в множестве
SOLO_COMMANDS в cmd_parser.py. Эти команды переписывают контекст.

Правила:

- В ||| SOLO нельзя вообще (ни в начале, ни в середине, ни в конце):
  результат SOLO переписывает контекст и затирает всё, что было до
  неё. Исключение — "в_контекст": false (или старый "в_буфер": false):
  тогда SOLO не трогает контекст и её можно ставить в любую позицию.
- Внутри "параллельно" — строгий режим: SOLO-команды разрешены
  только с "в_контекст": false. Иначе блок.
- NO_CTX_FALSE — команды, которые НЕ принимают "в_контекст": false
  (результат только в контекст): смотреть_видео, посмотреть_движение,
  прочитать_полностью, читать_полностью, рендер, отрендерить, открыть.
  В ||| (при >1 команде) и в параллельно запрещены. Если параметр
  в_контекст:false всё же передан — предупреждение + пропуск только
  этой |||-части, остальные команды выполняются. Если команда одна —
  только предупреждение, ничего не выполняется.
- NO_CTX_FALSE_NEEDS_SAVE — команды, у которых "в_контекст": false
  допустим только при наличии "сохранить": слушать_видео,
  кадр+субтитр, кадр. Без сохранения — отказ с требованием "сохранить".
- Алиас «кадр» (для «кадр+субтитр») идёт с "субтитр": false по
  умолчанию — без выжигания субтитров. SOLO-защита и
  NO_CTX_FALSE_NEEDS_SAVE работают и для алиаса.
- У «кадр», «кадр+субтитр», «слушать_видео»: если задан "сохранить",
  буфер по умолчанию не трогается (только файл). Явный
  "в_контекст": true — и файл, и буфер.
- Проверка в _collect_all_actions, _iter_solo_checks, _params_are_safe.

Пример: несколько "сгенерировать" в одном параллельно, только
на диск, буфер не трогают:

  {"параллельно": [
    {"сгенерировать": {"промпт": "...", "сохранить": "C:/s/01.png", "в_контекст": false}},
    {"сгенерировать": {"промпт": "...", "сохранить": "C:/s/02.png", "в_контекст": false}}
  ]}

Файлы

- PNG: profiles/<Агент>/memory/stabledif_out/<TS>_seed<seed>.png
- Лог: profiles/<Агент>/memory/stabledif.log
- PID: profiles/<Агент>/memory/stabledif.pid

Удаление текста (убрать_текст)
------------------------------

Автоматическое удаление текста с картинок: детектор текста + inpaint.

Пайплайн:
  1. DBNet ONNX детектит области с текстом.
  2. Маска (плотная, дилатация на расширить px).
  3. Inpaint: LaMa / SD / гибрид.

Модели и зависимости (всё вне anyjson):

- DBNet ONNX  — E:\StableDif\models\text_detection\dbnet.onnx
- big-lama    — E:\StableDif\webui\extensions\forge2_cleaner\models\big-lama.safetensors
- Расширение Forge — forge2_cleaner (в extensions/), предоставляет /cleanup
- Forge должен быть запущен (через run.bat, см. выше).

Патч расширения forge2_cleaner:

  scripts/api.py из коробки возвращает ошибку "Image has no len()" —
  lumen.clean_object возвращает PIL.Image, а не список. В точке /cleanup
  в репозитории лежит `if len(_output) > 0`. Патч (уже применён):

    _output = lama.clean_object(_image, _mask)
    if _output is None:
        return {"code": -1, "message": "Image generation failed"}
    _b64 = api.encode_pil_to_base64(_output)
    if isinstance(_b64, bytes):
        _b64 = _b64.decode("utf-8")
    return {"code": 0, "message": "ok", "image": _b64}

  При обновлении расширения патч может откатиться — переприменить.

Методы inpaint:

- lama    — быстро (~2-3 сек), big-lama. Хорошо для гладких фонов,
            шумно на лицах/сложных текстурах.
- sd      — SD-inpaint через /sdapi/v1/img2img. Качественно на сложных
            текстурах, но медленно (10-25 сек) и может галлюцинировать.
- гибрид  — по умолчанию. LaMa (грубо) → SD (дорисовка текстуры,
            сила 0.55). Лучший результат для портретов.

Параметры убрать_текст:

- путь        — входной файл (обязательно)
- метод       — lama / sd / гибрид (по умолч. гибрид)
- порог       — чувствительность DBNet, 0..1 (по умолч. 0.5).
                Меньше — больше пятен, но найдёт мелкий текст.
- расширить   — радиус дилатации маски в px (по умолч. 24).
                Для шрифтов с обводкой меньше 24 не хватает.
- мин_площадь — отсеять пятна меньше N px (по умолч. 40)
- сохранить   — путь к новому файлу. Без него — перезапись исходника
                и в буфер.
- только_маска — true: не звать inpaint, сохранить маску для отладки.

Только для sd и гибрид:

- промпт      — по умолч. "clean natural skin texture, smooth background, no text"
- негатив     — по умолч. "text, letters, words, watermark, writing, blurry, distorted"
- сила        — denoising_strength, 0.1..1.0 (по умолч. 0.85; для гибрида 0.55)
- шаги        — 1..50 (по умолч. 25)
- жёсткость   — CFG Scale (по умолч. 7.0)

Примеры:

  {"убрать_текст": {"путь": "C:/rpg/scene_01.png"}}
  {"убрать_текст": {"путь": "C:/in.png", "метод": "гибрид",
                    "промпт": "man's face, natural skin, soft bokeh",
                    "сохранить": "C:/out.png"}}
  {"убрать_текст": {"путь": "C:/in.png", "только_маска": true,
                    "расширить": 24, "сохранить": "C:/mask.png"}}

Отладка маски:

  Если инпейнт «не трогает» часть текста — сделай только_маску и
  наложи на оригинал через слои (multiply). Маска должна покрывать
  буквы с обводкой. Если меньше — увеличь расширить.

Сжатие текста (сжать_текст)
---------------------------

Сжатие текстового документа локальной моделью rut5-squeeze (T5).
Каждое предложение перефразируется короче; разделители (пробелы,
переводы строк) сохраняются как в оригинале. Числа, редкие символы,
парные скобки/кавычки проверяются — плохие сжатия откатываются
к оригиналу.

Модель и скрипты — внутри anyjson:

  side/external/squeeze/squeeze_document.py   — движок (T5)
  side/external/squeeze/squeeze_report.py     — обёртка (прогресс + отчёт)
  side/external/squeeze/rut5-squeeze/         — веса модели (~258 МБ)

Все пути резолвятся от Path(__file__).parent, хардкодов нет.

Команда

- сжать_текст / сжать_документ — сжать текстовый файл.
- подсказать_сокращения / где_сжать / кандидаты_сжатия /
  сжатые_абзацы — прогоняет файл через модель, показывает топ-N
  абзацев по сэкономленным байтам. Никуда не сохраняет.

Параметры:

- вход  — путь к исходному файлу (обязательно)
- выход — путь к результату (обязательно)
- до    — целевой размер ("100КБ", "1МБ", 50000). Включает
          итеративный режим: сжимать, пока файл больше цели
          и сжатие за итерацию не упадёт ниже 1%.
- тихо  — true: не транслировать прогресс в консоль, только итог.

Авто-подбор

Перед запуском squeeze_report.py оценивает время по числу предложений
и таблице реальных скоростей. Бюджет: beams==1 — без лимита,
beams==2 — 60 сек, beams>=3 — 30 сек. Если оценка выходит за бюджет,
качество понижается, а при необходимости включается fast-режим
(рискованные предложения — пути, идентификаторы с _, отрицания,
числа — не отправляются модели, остаются как есть). В начале вывода
печатается одна строка: `[i] оценка ~N сек`. С параметром `отладка:
true` — расширенная: `[i] авто: beams=X, fast=Y, предложений=N,
оценка ~Z сек`.

Дедуп (при fast)

Если авто-подбор включил fast-режим, squeeze_report.py считает
уникальные предложения и, если их меньше общего числа, пересчитывает
бюджет по ним. Одинаковые предложения отправляются в модель один раз,
а на выходе остаётся одна копия (не размножается обратно). Дедуп
включается только в fast — в обычном режиме пост-проверки не дают
двум разным входам схлопнуться в один выход.

Прогресс

Каждые 100 предложений — `[i] N/M (X.X предл/сек)`, плюс финальная
строка. По завершении — отчёт: размеры, процент сжатия, число
сжатых строк, первые 10 сжатых абзацев (IN/OUT).

Пример

  {"сжать_текст": {"вход": "E:/docs/article.txt",
                    "выход": "E:/docs/article_short.txt"}}

Подсказать сокращения

  {"подсказать_сокращения": {"вход": "E:/docs/article.txt",
                              "топ": 10}}

Параметры: вход, топ (по умолч. 10), мин_длина (по умолч. 5 Б),
тихо. Прогоняет файл, ничего не сохраняет. Показывает абзацы
с наибольшей экономией в формате:

  1. −N Б
     Оригинал: <абзац до>
     Например: <абзац после>

Полезно для прозы — оценить, есть ли что сокращать. На технической
документации (JSON, код, пути) модель врёт, подсказкам не доверять.

Защиты в squeeze_document.py (откат к оригиналу)

- длина: если сжатие вышло не короче оригинала — откат;
- числа: все числовые токены из src должны присутствовать в dst
  (с учётом ratio 1:16 ↔ 1 к 16);
- редкие символы: ₽≈≤≥±°¹²³ и диакритика — если символ был
  в src, но пропал в dst — откат;
- пары: баланс «», (), [], {} должен сохраниться;
- paths: Windows-пути из src должны сохраниться в dst;
- identifiers: идентификаторы с подчёркиванием (_core, _ps, _actions)
  должны сохраниться;
- negations: число «не / нет / ни» в dst не должно быть меньше, чем в src;
- стоп-фразы: список галлюцинаций-связок («можно сказать»,
  «было установлено», «учёные оценили») — если фраза появилась
  в сжатии, откат.

Если ничего не сжалось — «Ничего не сжалось.» Это норма для
текста, где модель не видит, что сократить (числа, имена,
короткие предложения уже плотные).

Ограничения

- Для прозы. На технической документации (пути, JSON,
  markdown-таблицы) защита ловит не всё: смысловые замены типа
  «останется → оставится» могут проскочить.
- Много итераций накапливает ошибки. Первый проход по прозе даёт
  ~20%, второй — 1-2%, третий — 0%. Режим `до` крутит итерации,
  пока размер больше цели, но останавливается на сжатии < 1% —
  это защита от бесконечного ухудшения.
- Модель видит предложения, не разметку. В markdown-таблицах
  ломает `|` и `**`.

Производительность (GTX 1050 Ti, загрузка модели ~13 сек)

- 46 предл (7 КБ)    — 18 сек, beams=8
- 256 предл (41 КБ)  — 28 сек, beams=4 fast
- 1006 предл (162 КБ) — 44 сек, beams=2 fast

Скорость предл/сек в таблице _SPEED_TABLE калибрована по этим
замерам. Оценка попадает в факт с точностью ±5% на средних
и больших файлах.

Окно в мир (SkylineWebcams)
---------------------------

Кадр с публичной веб-камеры SkylineWebcams → буфер.

Параметры

- страна — код в URL Skyline (italia, deutschland, ellada, united-states, russia, …) — обязательный
- регион — страница региона (lazio, veneto, crete, new-york, …)

Команды (сводка)
----------------

Полный список команд — в рантайме:

  {"список_команд": {}}              — случайная выборка
  {"диагностика": {"сервис": "..."}}    — поиск по имени/доку/параметрам
  {"справка": "имя_команды"}        — докстринг конкретной команды

Все команды зарегистрированы в HANDLERS (см. «Регистрация команд»)
и доступны через «диагностика» с транслитерацией: moltbook ↔ молтбук,
text ↔ текст, number ↔ номер.

Докстринги и подсказки
----------------------

При ошибке команды в ответ докидывается её докстринг:

❌ Ошибка погода: не указан город

📖 Справка:
Команда "погода".

📌 Недостающие параметры:
  • дней

- _doc_for(action, error_text) — берёт докстринг, фильтрует тавтологию
  (если параметр уже назван в ошибке — не повторяется).
- _extract_params_ast(fn) — вытягивает параметры из тела функции через AST,
  не задевая соседние функции.
- wrap_json_hints(text) — оборачивает JSON-команды в  `text .
  Понимает отступы.

Для недоступных функций (❌ Личные сообщения сейчас недоступны) справка
не добавляется — чтобы агент не искал обходные пути.

Общие алиасы параметров (_apply_param_aliases в cmd_parser.py)

Некоторые пары ключей автоматически дублируют друг друга, чтобы
LLM не спотыкался о синонимы. Работает для всех команд сразу:

- лимит ↔ количество
- url ↔ урл ↔ ссылка ↔ адрес
- запрос ↔ query

Если команда ждёт «количество», а пришло «лимит» — значение
подставится в оба ключа, предупреждения «неизвестные параметры»
не будет. `_check_unknown_params` знает про эти пары и не ругается.

Команды с динамическими параметрами (_any_params)

Если команда принимает ПРОИЗВОЛЬНЫЕ ключи (например,
предсказать_продолжение принимает имена признаков t/x/y/…,
сим_команда принимает любые поля JSON, молтбук_запрос — урл/метод/тело),
её функция в модуле помечается флагом:

    predict_continuation._any_params = True

Тогда _check_unknown_params пропускает такую команду и не пишет
«⚠️ неизвестные параметры». Применяется в oracul.py, sim.py,
moltbook_extra.py.

Диагностика
-----------

{"диагностика": {"сервис": "moltbook"}}
{"диагностика": {"сервис": "text", "где": "параметр"}}
{"диагностика": {"сервис": "путь", "где": "всё"}}
{"диагностика": {"сервис": "text", "лимит": 5}}
{"диагностика": {"сервис": "text", "лимит": 0}}

Ищет команды по имени / докстрингу / параметрам. Понимает транслитерацию:
moltbook ↔ молтбук, number ↔ номер ↔ нумбер, text ↔ текст.

Сортирует по релевантности: точное имя > алиас > подстрока имени >
параметр > докстринг. По умолчанию показывает топ-10 и хвост
«… и ещё N». Параметр лимит меняет размер выборки; 0 или «все» —
без лимита.

Технические заметки
-------------------

Выжимка из истории разработки. Места, где легко наступить на грабли.

ControlNet через Forge API

- Поле image, не input_image. ControlNetUnit.from_dict() читает
  unit.image. Только input_image — падает на «no input image».
- module: "None" с большой буквы. "none" строчными даёт
  NoneType.corp_image_with_a1111_mask....
- Имя модели — с хешем: control_v11p_sd15_openpose_fp16 [73c2b67d].
  Короткое имя даёт KeyError. Если нет хеша — искать в
  /controlnet/model_list.

/cleanup 404 после старта Forge

Forge отвечает на /sdapi/v1/options раньше, чем расширения
регистрируют endpoint. /cleanup появляется через 3–5 секунд.
_ensure_forge_alive ждёт /cleanup в /openapi.json до 60 секунд.

Hot-reload: тонкости

- README — не hot-reload. Правки только перезаписью в файл.
- anyjson.py — не hot-reload: здесь REPL и разбор <<<...>>>.
  Любая правка heredoc/||| требует перезапуска anyjson.
- _actions/cmd_parser.py — reload иногда падает тихо. После правок
  перезапустить anyjson.
- _core/_py_guard.py — не hot-reload в обычном смысле: он вообще
  не загружается в процесс anyjson. Команда «питон» запускает его
  как отдельный процесс на каждый вызов, так что правки подхватываются
  сразу, без reload. В _actions/__init__.py он внесён в _CORE_SILENT,
  поэтому ложного warn «перезапусти anyjson вручную» не выводится.
- Новый _actions/*.py подхватится автодискавером
  (load_all через pkgutil.iter_modules) при следующем reload_if_changed.
  Ничего в _actions/__init__.py прописывать не нужно.
- Новый контейнер команд (как параллельно) — проверить, что
  _extract_actions и _iter_solo_checks заходят внутрь, иначе
  SOLO-защита не работает для вложенных.

Уроки рефакторинга lottie (уникальное, без дублей с «Правила патчей»)

Перестановка глобалов. При выносе X в _state.py нельзя сначала
заменить X → _state.X, а потом чистить global X — получится
"global _state.X" и SyntaxError. Сначала фильтруй global-строки
(по чистому имени), только потом заменяй в остальных.

Мёртвый код перед удалением. Проверь, что в «дубликате» нет
уникального: parse_anim_shorthand была дважды (L130/L1953),
первая в кадрах, вторая в секундах, живая — вторая. В первой

Скрытые зависимости. parse_tr считалась «остаётся в монолите»,
но единственный потребитель — keyframes_to_points в _anim.py.
Правило: перед выносом проверь ВСЕХ вызывающих.

Импорт в новый модуль. Забытый import math/re/X ловится сразу:
import модуля в питон-тесте даёт NameError до прогона эталонов.

Smoke-тест — на реальных входах. parse_gradient('...red, blue')

Сравнение эталонов. Игнорируй nm и meta.source (зависят от имени

Автооткат при импорте. Все питон-патчи делают бэкап и при

Правила патчей (PS, здесь и сейчас)

- Спорит — значит не применял. Если пользователь обсуждает патч,
  возражает — проверить файл, не полагаться на «уже должно быть».
- Не видел подтверждения — не выполнено. Прислал оператор «✅ Заменено N»
  или diff — применено; иначе — нет. Readme не hot-reload: каждая
  правка проверяется отдельно (осмотреть по уникальному слову).
- replaced: 0 — не следующий шаг, а искать причину: якорь не найден.
- Не просить куски файла. Дай полный путь — пользователь откроет.
- Heredoc не интерпретирует \n, \t, \r — внутри пиши литеральные
  переносы (Enter), либо «питон» с write_text(encoding="utf-8"),
  либо PS-скрипт (там `n — реальный перенос). Проверено: \n в heredoc
  дал «慜湡屮扜» — это битая кодировка ЗАПИСИ (UTF-8 прочитан как
  UTF-16), не баг чтения. Пересоздай через «питон» с utf-8.

Стоп-слова и алиасы в параметрах

- питон: стоп-слова по regex (\bexec\s*\() — "exec" in script
  ловит sys.executable и даёт ложное срабатывание.
- wav/sounds как алиасы звук — добавить в BAD
  _extract_params_ast, чтобы не светились в подсказках.
- в_буфер — тоже в BAD.
- SMIL в SVG: _apply_smil_at_to_last в rect/circle/ellipse (раньше
  только polygon); r0 для scale из r, не из кейфрейма; rotate между
  циклами кумулятивный (0→360→720→1080). Проверено на mp4.

- Параметр, спрятанный в хелпер, невидим для диагностики.
  _extract_params_ast видит только литеральные args.get("X") в теле
  функции. Если ключ читается через хелпер-обёртку вида
  _flag("X", default), внутри хелпера стоит args.get(name) с
  переменной name — AST видит Name('name'), а не Constant("X"), и
  параметр пропадает из автоподсказки диагностики. Команда работает,
  но пользователь видит «⚠️ неизвестные параметры: X». Лечится
  перестановкой: хелпер принимает готовое значение, а ключ в теле
  функции остаётся литералом:
      def _as_bool(v, default=False): ...
      dry = _as_bool(args.get("предпросмотр"), False)
  Проверено на дедуплицировать_строки: 6 параметров были невидимы,
  после перестановки — все 10 видны.

Tor и Tavily

Tor не поднят — ключ Tavily не спрашивается, в search_multi
задание tavily не создаётся. В лог: «Tor не поднят — Tavily
пропущен, только DDG».

питон и guard

- CWD процесса «питон» — E:\Jericho (родитель anyjson), а не BASE_DIR.
  Это осознанно: «отсюда стартовать». Относительные пути в скрипте
  резолвятся от E:\Jericho. Для BASE_DIR — absolute path.
- _py_guard.py запускается как отдельный процесс на каждый «питон»,
  поэтому правки в нём подхватываются сразу, hot-reload не нужен.
- os._exit(3) в guard — намеренно, не sys.exit. sys.exit поднимает
  SystemExit, который можно поймать try/except внутри агентского
  скрипта. os._exit убивает процесс немедленно и не ловится.
- audit hook не покрывает socket.connect, urllib, ctypes. Если модель
  угрозы расширится (агент не должен лезть в сеть) — добавить
  соответствующие events в _audit.
- PYTHONUNBUFFERED: любой subprocess с python-скриптом (через
  _run_py) должен передавать env["PYTHONUNBUFFERED"]="1", иначе
  print() без flush=True копится в блок по 4-8 КБ и не стримится.
  Без этого 300-кадровый рендер «молчит» минуту.
- svg2lottie_v6.py: svg_main использует parse_css (урезанный парсер),
  а не css_parse (полный). При правках CSS-парсинга патчить именно
  parse_css — иначе изменения в css_parse не видны.
- __future__: from __future__ import annotations — разрешённый импорт,
  добавлен в ALLOWED_STDLIB в _core/_validate_imports.py.
- _py_guard.py не защищён от «удалить_файл» — файл внутри BASE_DIR,
  а «удалить_файл» BASE_DIR не защищает. Оставлено осознанно: любой,
  кто может править _actions/*.py, и так сильнее guard'а. Защита от
  случайного сноса, не от саботажа.

Что важно помнить
-----------------

• Все имена команд — на кириллице. Латиница → блок.
• Чужой .py не запустить — кроме как через «питон».
• API-ключи — через ensure_api_key(), автоматически.
• Tor — для Moltbook и Tavily. Есть тор_запрос — всегда через Tor.
• Hot-reload — _actions/*.py и часть _core/* подхватываются на лету.
• Heredoc — для длинных текстов. >>> сам выполняет.
• UNaIVERSE agent-to-agent — не работает (их баг).
• Никаких хардкод-путей. Все пути — от BASE_DIR, side/config.json или env-var. anyjson работает из любой папки: переместил — и всё живо.
• Общие эталоны — data/etalons/. Для видео и аудио — один
   набор (speech + tembr). Ищется вверх по дереву от __file__,
   без хардкода.
• UAC — не проблема. Windows-запросы на подтверждение (UAC) — норма. Forge, zapret, симулятор и другие процессы, которые требуют повышенных прав, запускаются через ShellExecuteW(..., 'runas', ...) — Windows покажет окно подтверждения. Не считать это ошибкой и не пытаться обходить. Оператор подтвердит.

• Агент не знает про буфер. В докстрингах и параметрах команд не должно быть слова «буфер» — ни в_буфер, ни «кладётся в буфер», ни «посмотри картинку». Агент получает результат как обычный текст.
    Оператор видит буфер по маркеру [BUF] 📋 ... в консоли. Это часть вывода для человека, не для агента.
    В _extract_params_ast подстрока буфер входит в стоп-слова (BAD), поэтому параметр в_буфер не всплывает в подсказках.

• IPv4-only резолв. _config.py переопределяет
    socket.getaddrinfo — только AF_INET. Это убирает ошибки
    getaddrinfo failed, когда локальный DNS отдаёт IPv6 первым,
    а IPv6 в сети не работает.

• Имя агента — всегда первым аргументом. Без него _ask_name() уйдёт
    в input() и зависнет в subprocess / CI. _flush_console_input()
    после input() сливает остаток многострочной вставки — иначе
    вторая строка попадёт в REPL как команда.

• Опечатки в параметрах — предупреждение. _check_unknown_params в
    cmd_parser.py сверяет ключи с _extract_params_ast и дописывает
    в результат: «⚠️ команда: неизвестные параметры: X, Y» +
    справку через _doc_for. Сама команда выполняется, но пользователь
    видит, что что-то не то.

• Алиас параметра не светится в подсказках. Легаси-алиас (например,
    wav у наложить_звук) добавляй в BAD-фильтр в
    cmd_parser._extract_params_ast. Код продолжит работать, но в
    диагностике будет виден только канонический параметр (звук).

• Гонка /cleanup при старте Forge. Forge отвечает на
    /sdapi/v1/options раньше, чем расширения регистрируют endpoints.
    _ensure_forge_alive ждёт /cleanup в /openapi.json до 60 секунд.
    Подробности — в «Технические заметки».

• Forge гасится при выходе anyjson. capture_forge_pid в stabledif.py
    находит PID процесса на порту 7860 и пишет в MY_DIR/stabledif.pid,
    даже если Forge был запущен вручную. При выходе — taskkill /T /F.
    См. «Внешние инструменты и пути».

• Кадр/слушать_видео — предпроверка секунды через ffprobe: если
    секунда >= длительности, возвращается точное сообщение с
    допустимым диапазоном (вместо CLI-ошибки «не прочитать кадр»).
