# anyjson

Инструмент, которым **внешний LLM** (DeepSeek, GPT и т.п.) пользуется через JSON-команды.
Пользователь вводит JSON в консоль anyjson — команды выполняются. Обратной связи
«LLM внутри anyjson» нет, LLM снаружи.

---

## Быстрый старт

```powershell
cd E:\Jericho\anyjson
py anyjson.py Ассистент
```

Без аргумента — спросит имя агента.
Профиль и рабочие файлы создаются в `profiles\<Агент>\memory\`.

---

### Имя агента

Имя задаётся **первым аргументом** командной строки:

~~~powershell
py anyjson.py Ассистент
py anyjson.py "Мой Агент"
~~~

Несколько аргументов склеиваются через пробел:

~~~powershell
py anyjson.py Мой Агент      # то же, что "Мой Агент"
~~~

**Без аргументов** anyjson спросит имя интерактивно (`_ask_name()`, `input("> ")`).
В скрипте / subprocess / CI так **нельзя** — зависнет или упадёт с `EOFError`.
Всегда передавай имя первым аргументом.

Из имени вычищаются `< > : " / \ | ? *`, скобки, кавычки, запятые и управляющие
символы (`_sanitize_name`). Пробелы и дефисы остаются. Результат — имя папки
`profiles\<Агент>\memory\`.

Файл `side\config.json` обязателен — без него `_config.py` делает `sys.exit(1)`
с сообщением «Караул! Скрижаль Конфигурации утеряна».

## Формат ввода

Одна команда:

```json
{"имя_команды": {"параметр": "значение"}}
```

Несколько команд в одной строке — через `|||`:

```json
{"эхо": {"текст": "hi"}}|||{"время": {}}
```

Многострочный JSON — копится в буфере. Для выполнения нужно **две пустые строки**
(для JSON, начинающегося с `{` или `[`, достаточно одной).

### Heredoc — для длинных текстов и кода

```
{"переписать": {"путь": "C:/temp/x.py"}}
<<<
import os
x = "любые кавычки"
print(x)
>>>
```

Правила:

- `<<<` открывает блок;
- `>>>` закрывает **и сразу выполняет** (пустая строка после — не нужна);
- внутри блока ничего не экранируется;
- то же работает для `{"питон": {"скрипт": "X"}}`.

### Импорты

`anyjson.py` добавляет в `sys.path`:

- `_CORE` (`_core/`) — для `_config`, `_utils`, `_executor`, `_ps`, `_tor`, `_storage`, `_web`, `_safe_subprocess`.
- `_HERE` (`anyjson/`) — для `_actions`.

Пакет `tools` и старый `tools.py` **удалены**. Всё, что было там, переехало в
`_actions/_tools_*.py` и `_actions/tools_*.py`.

## Поток выполнения

1. `python anyjson.py <AGENT_NAME>`
2. `main()`:
   - `_tools_core.init_tools(BASE_DIR, AGENT_NAME, ...)` — инициализация инструментов
   - `_safe_init_moltbook()` — если есть ключ `moltbook`
   - `SensorCore` — **лениво**, при первой state-команде
   - `load_processed_messages()`, `atexit(cleanup_tor)`, `atexit(save_processed_messages)`
   - `check_inbox()` → вывод + в буфер
   - `load_reminders()` + фоновый поток `reminder_checker`
   - `ensure_loaded()` + `load_all()` — импорт `_actions/*.py`, наполняющих HANDLERS
   - валидации: импорты (`_validate_imports`), пути модулей (`_validate_module_paths`)
3. REPL читает stdin, копит многострочный JSON.
4. `process_command_input(text)` парсит JSON → `HANDLERS["имя"](параметры)`.

## Регистрация команд

```python
from _actions import register

@register(["читать", "прочитать", "прочитай"])
def read_(args: dict) -> str:
    ...
    return "ответ"
```

`HANDLERS[name] = func` — для каждого имени.

### Правило имён

Все имена команд — **только на кириллице** (плюс цифры и `_`).
Любая латиница в имени команды **блокируется** с подсказкой русского аналога:

```
❌ Команда "echo" — латинский алиас, используй русское имя:
  • "эхо"
```

Если латинское имя зарегистрировано, но у него есть кириллический брат-близнец —
подсказка покажет **русское имя**. Если нет — общая подсказка
`❌ Название команды должно быть на русском, например: ...`.

## Фильтры безопасности

### 1. Страж `subprocess` (`_core/_safe_subprocess.py`)

Любой `.py` можно запустить **только** внутри `BASE_DIR`.
Исключение — контекст `allow_external_py()`, который выставляет **только**
команда «питон».

- Чужой `.py` → `ExternalPyBlocked`.
- `python -c "..."` (inline) → пропускается.
- `python -m module` → пропускается.
- Не-питоновые команды (ffmpeg, curl, cleanmgr, ...) → не трогает.

### 2. Запрет записи

`{"переписать"}` и `{"добавить"}` запрещают запись в:

- `C:\Windows`
- `C:\Program Files`
- `C:\Program Files (x86)`
- `C:\ProgramData`

### 3. Ограничения `{"питон"}`

В **тексте скрипта** блокируются слова: `os.system`, `subprocess`, `__import__`,
`eval`, `exec`, `socket`, `requests`.

### 4. `leak_guard`

Блокирует отправку во внешние сервисы (Moltbook, UNaIVERSE) текста с секретами:

- `password`, `passwd`, `pwd`, `passphrase`,
- `api_key`, `apikey`,
- `private_key`, `secret_key`,
- `token`, `secret`, `bearer`, `authorization`,
- форматы: `sk-...`, `xoxb-...`, `ghp_...`, `Bearer ...`, длинные hex (40+).

## API-ключи

Хранятся в `side/api_keys.json`:

```json
{
  "tavily": "tvly-...",
  "wolfram": "...",
  "moltbook": "moltbook_sk_...",
  "unaiverse": "..."
}
```

Получить ключ в рантайме:

```python
from _config import ensure_api_key
key = ensure_api_key("tavily")   # спросит и сохранит, если нет
```

Если ключ **не нужен** сейчас — не спрашивает. Если нужен и его нет —
prompt в главном потоке, ввод скрыт (`getpass`/`msvcrt`), сохраняется в файл.

## Tor

- **ControlPort 9051** — для ротации exit-нод (`stem`, `NEWNYM`).
- **`torrc`** — в конфиге (`_TORRC`). Добавлены:

  ```
  ControlPort 9051
  CookieAuthentication 0
  MaxCircuitDirtiness 60
  NewCircuitPeriod 30
  ```

- **`new_circuit(wait_sec=2.0)`** — запросить новую exit-ноду.
- **Retry в Moltbook** — при CloudFront 403 и timeout (до 10 попыток с ротацией).
- **Tavily** — только через Tor (`socks5h://127.0.0.1:9050`). Напрямую из РФ → 403.

## UNaIVERSE

Пакет `unaiverse` (0.1.12) — P2P-сеть агентов.

### Команды

| Команда | Что делает |
|---|---|
| `юнайверс_запустить` | запустить демон в фоне |
| `юнайверс_остановить` | мягко остановить |
| `юнайверс_статус` | статус + хвост лога |
| `юнайверс_лог` | хвост лога с фильтром и контекстом |
| `юнайверс_найти` | глобальный список узлов (`/nodes/get`) |
| `юнайверс_подключиться` | подключиться к агенту |
| `юнайверс_войти_в_мир` | войти в мир |
| `юнайверс_покинуть` | покинуть всё |
| `юнайверс_входящие` | прочитать inbox |
| `юнайверс_ответить` | отправить текст |
| `юнайверс_запрос` | прямой POST к `/api/...` |

### Особенности

- **`Agent(HumanModule with explicit streams)`** — text-only.
  **Не объявляем img-выход**, иначе UNaIVERSE открывает камеру (`cv2.VideoCapture(0)`).
- **`asyncio.sleep` ≥ 0.05s** — их главный цикл вызывал `sleep(0.001)` и жёг ядро.
- **`prompt_toolkit.patch_stdout`** → no-op, `prompt()` → заглушка. Иначе падает
  на отсутствии консоли.
- **`stdin=DEVNULL`** у демона — чтобы не перехватывал REPL-ввод.
- **`NODE_IGNORE_ALIVE=1`** — обход серверной блокировки имени (безопасно, потому
  что мы сами гарантируем отсутствие дублей через PID-файл и `_kill_orphan_agents`).
- **Демон запускается с `CREATE_NO_WINDOW`**, но при этом `CREATE_NEW_PROCESS_GROUP`.
- **Файлы обмена** (в `MY_DIR`): `unaiverse_cmd.jsonl`, `unaiverse_result.jsonl`,
  `unaiverse_inbox.jsonl`, `human_input.txt`, `unaiverse.log`, `unaiverse.pid`.

### Известные ограничения (v0.1.12)

- **Agent-to-agent P2P не работает** — `ask_to_get_in_touch` падает с
  `Connection failed!` до ping-pong (relay `misc.unaiverse.io` не пропускает
  агент-агент трафик).
- **Браузер ↔ агент тоже не работает** — та же проблема.
- **World join работает** (ChatRoom подключался), но broadcaster молчит.

Это **баг их платформы**, не наш. Ждём обновления.

- 300 секунд на молтбук-команды.

  1. Успех → ок.
  2. Первое предупреждение → `⏸️ ... Следующая разрешена с HH:MM:SS`.
  3. Спам → `⏸️ За спам время ожидания увеличено на 5 минут`.
- В сообщении — три случайные команды через `{"помощь": "..."}`.

подробностей.

## Stable Diffusion (Forge)

Генерация картинок через локальный Forge (форк A1111).

### Путь и конфиг

В `side/config.json`:

~~~json
{
  "paths": {
    "stabledif_dir": "E:/StableDif"
  }
}
~~~

В `_config.py` оттуда растут `STABLEDIF_DIR`, `STABLEDIF_RUN`,
`STABLEDIF_HOST`, `STABLEDIF_PORT`. Никаких хардкодов в `*.py`.

### Запуск

`webui-user.bat`:

~~~text
set COMMANDLINE_ARGS=--api --nowebui --server-name 127.0.0.1 --port 7860
~~~

- `--api` — REST API включён
- `--nowebui` — только API, без UI и без авто-открытия браузера
- `--server-name 127.0.0.1` — слушает только локально
- `--port 7860`

`нарисуй` **сам поднимает Forge**, если API не отвечает. Руками `run.bat`
дёргать не надо. Прогресс старта: `Forge стартует... Ns ####`.
После первого запуска Forge остаётся в фоне — следующий `нарисуй` мгновенный.

Остановить вручную: `{"стабилдиф_остановить": {}}`.

### Параметры `нарисуй`

- `промпт` — обязательно
- `негатив`
- `ширина` / `высота` — по умолчанию 512×512
- `шаги` — sampling steps, по умолчанию 20
- `cfg` — CFG Scale, по умолчанию 7.0
- `seed` — по умолчанию -1 (случайный)
- `сэмплер` — `Euler a` по умолчанию
- `модель` — имя чекпойнта, переключает на лету
- `в_буфер` — true по умолчанию
- `сохранить` — путь для PNG (иначе `MY_DIR/stabledif_out/`)

Пример:

~~~json
{"нарисуй": {"промпт": "cat in a hat, oil painting",
             "негатив": "blurry, low quality",
             "ширина": 768, "высота": 768, "шаги": 30}}
~~~

### Прогресс

Во время генерации — `Осталось N сек.` (обновляется в той же строке, не спамит).
ETA берётся из `/sdapi/v1/progress`.

### BUF_COMMANDS

`стабилдиф`, `нарисуй`, `сгенерировать`, `txt2img` — в списке `BUF_COMMANDS`
в `cmd_parser.py`. Их **нельзя** смешивать с другими командами в `|||`
(гонка за буфер). Отдельной командой.

### Файлы

- PNG: `profiles/<Агент>/memory/stabledif_out/<TS>_seed<seed>.png`
- Лог: `profiles/<Агент>/memory/stabledif.log`
- PID: `profiles/<Агент>/memory/stabledif.pid`

## Команды (сводка)

При ошибке команды в ответ **докидывается** её докстринг:

❌ Ошибка погода: не указан город

📖 Справка:
Команда "погода".

📌 Недостающие параметры:

Для недоступных функций (`❌ Личные сообщения сейчас недоступны`) справка
**не добавляется** — чтобы агент не искал обходные пути.

## Что важно помнить

1. **Все имена команд — на кириллице.** Латиница → блок.
2. **Чужой `.py` не запустить** — кроме как через «питон».
3. **API-ключи** — через `ensure_api_key()`, автоматически.
4. **Tor** — для Moltbook и Tavily.
5. **Hot-reload** — `_actions/*.py` и часть `_core/*` подхватываются на лету.
6. **Heredoc** — для длинных текстов. `>>>` сам выполняет.
7. **UNaIVERSE agent-to-agent** — не работает (их баг).
8. **Никаких хардкод-путей.** Все пути — от `BASE_DIR`, `side/config.json` или env-var. anyjson работает из любой папки: переместил — и всё живо.
9. **Общие эталоны — `data/etalons/`.** Для видео и аудио — один
   набор (speech + tembr). Ищется вверх по дереву от `__file__`,
   без хардкода.

## Режим работы: через PowerShell

anyjson правится **PS-командами**, а не «сохрани файл в редакторе».

### 1. Разовый код — `py -c`

~~~powershell
py -c "print(1+1)"
~~~

### 2. Многострочно — PS here-string `@" ... "@`

~~~powershell
py -c @"
import sys
print(sys.version)
"@
~~~

Правила: `@"` и `"@` — на своей строке, `"@` в самом начале, отступов нет.

**Осторожно:** `@" ... "@` подставляет `$переменные`. Если в Python-коде есть `$` — бери `@' ... '@` или массив строк.

### 3. Патч файла — массив single-quoted строк

**Главное правило:** если в патче есть markdown-с-бэктиками или много `'`,
используй массив `@('...', '...')`, а не `@'...'@`.

~~~powershell
$lines = @(
    'import pathlib',
    'p = pathlib.Path(r"E:\Jericho\anyjson\Readme.md")',
    'print(p.read_text(encoding="utf-8")[:200])',
)
$src = $lines -join "`r`n"
Set-Content E:\Jericho\anyjson\side\_patch.py -Value $src -Encoding utf8NoBOM
python E:\Jericho\anyjson\side\_patch.py
Remove-Item E:\Jericho\anyjson\side\_patch.py
~~~

### 4. Markdown с бэктиками

`@'...'@` (одиночный here-string) **рвётся** на длинном тексте с бэктиками и `'`.
Два надёжных способа:

1. **Массив строк** `@('...', '...')` — каждая строка парсится независимо,
   `'` экранируется как `''`, всё остальное (` `` `, `#`, `$`, `@`) — литерал.
2. **`~~~` вместо ` ``` `** — тильда в PS не имеет спецсмысла вообще.

### 5. Работа с файлами — проси полный путь

**Главное правило сессии.** Если нужно посмотреть содержимое файла — **не проси `py`-скрипт**,
**не проси «покажи первые N строк»**, **не режь на куски**. Просто скажи: «дай полный путь».
Пользователь вставит содержимое целиком, одним сообщением.

**Плохо:**

~~~text
Скинь py-команду, которая прочитает первые 100 строк C:\temp\big.svg
~~~

**Хорошо:**

~~~text
Дай полный путь к big.svg — я открою целиком.
~~~

Это правило перебивает любые другие: даже если файл большой, «кусочный» вывод
через `py -c`, `head`, `Select-Object -First N` — **не предлагать**. Пользователь сам
решит, сколько показать.

### 5.1 Кавычки в PS-массиве — главная ловушка

Внутри `@('...', '...')` каждая строка закрывается на первой `'`. Если внутри
строки есть `'` (а в Python-коде они повсюду) — PS сломается на
`ParserError: Непредвиденный токен`.

**Правило:** каждую одиночную `'` внутри `'...'` писать как `''` (две).
Так работает любой PS.

~~~powershell
$lines = @(
    'print("hi")',
    's = ''it''''s ok''',        # в Python: s = ''it''''s ok''
    'from _actions import register',
)
~~~

Второй способ — вообще избежать кавычек: **в Python-коде писать только `"`**,
а одиночных `'` не иметь. Тогда PS-массив не требует экранирования. Так
делались все патчи этой сессии, кроме того, где я забыл.

~~~powershell
$lines = @(
    'print("hi")',              # в Python: print("hi")
    's = "it''s ok"',            # в Python: s = "it''s ok" — PS: '' -> '
)
~~~

**Если в строке много `'`** — бери `@'...'@` (single-quoted here-string),
а не массив. Внутри него ничего не экранируется.

**Если и в `@'...'@` сложно** — вынеси Python-скрипт в `side\_patch.py`
через базовый `[IO.File]::WriteAllText` и `@'...'@` — самый устойчивый путь.

### 6. Экранирование бэкслэшей

**Правило:** в PS-строке `\` — это **литерал**, а не escape-символ. Escape-символ в PS — бэктик (`` ` ``). Значит, в массиве `@('...', '...')` пиши **ровно то, что хочешь видеть в `.py`-файле**. Ничего не удваивай "для PS".

~~~text
Цель в .py-файле              | Как писать в PS-массиве @('...', '...')
------------------------------|-----------------------------------------
p = Path(r"C:\temp")          | 'p = Path(r"C:\temp")'
s = "C:\\temp"                 | 's = "C:\\temp"'
re.sub(r"\\", "/", s)          | 're.sub(r"\\", "/", s)'
print("a\nb")                 | 'print("a\nb")'
~~~

В PS **одинарные** кавычки не трогают `\` вообще. Но бэктик внутри `'...'` остаётся литералом — если надо передать `` ` ``, пиши его как есть.

**Плохие ловушки:**

~~~text
Что написал в PS-массив         | Что оказалось в .py-файле     | Что видит Python
--------------------------------|-------------------------------|------------------
's = "C:\temp"'                | s = "C:\temp"                | C:<TAB>emp
                                |                               | (\t = tab!)
's = "C:\\temp"'              | s = "C:\\temp"              | C:\temp  (правильно)
~~~

**Если бэкслэшей много — избегай их вообще:**

- Пути — через прямой слэш: `Path("C:/temp")` работает и на Windows.
- Нужен литеральный `\` в Python-строке — пиши `chr(92)`. PS-массив не трогает `chr(92)`, Python получает ровно `\`.

~~~powershell
# Плохо — четыре бэкслэша, считать в голове:
$lines = @('    s = s.replace("\\\\", "/")')

# Хорошо — однозначно:
$lines = @('    s = s.replace(chr(92), "/")')
~~~

### 7. Запуск anyjson из скрипта

Имя агента — **обязательно** первым аргументом. Без него `_ask_name()` уйдёт в
`input()` — в subprocess это зависание или `EOFError`.

~~~powershell
py E:\Jericho\anyjson\anyjson.py Художник
py E:\Jericho\anyjson\anyjson.py Мой Агент
~~~

Из Python:

~~~python
import subprocess
subprocess.run(["py", r"E:\Jericho\anyjson\anyjson.py", "Художник"], check=False)
~~~

Одноразовая команда без входа в REPL:

~~~powershell
'{"эхо": {"текст": "hi"}}' | py E:\Jericho\anyjson\anyjson.py Художник
~~~

### Договор

1. Кодировка — `-Encoding utf8NoBOM` (PS 7+).
2. Временные скрипты — в `side\`, удаляются сразу.
3. `anyjson.py` — не hot-reload, перезапуск. `_actions/*.py` — reload сами.
4. Markdown — через массив строк или `~~~`, не через `@'...'@`.
5. Python-патчи пиши **без одинарных кавычек** (только `"`), тогда PS-массив не требует экранирования.
6. `@"..."@` в PS подставляет `$переменные` — если в коде есть `$`, бери `@'...'@`.
7. **Не проси читать куски.** Проси полный путь — пользователь пришлёт файл целиком.
8. **`'` внутри PS-массива → `''`.** В `@('...', '...')` любая `'` внутри
   строки должна быть `''`. Если так лень считать — пиши Python-код без
   одинарных кавычек, только `"`. Для длинных патчей — `@'...'@`
   через `[IO.File]::WriteAllText`.

8. **Никаких хардкод-путей.** anyjson должен работать из любой папки — переместил и всё живо.
   - В Python — от `BASE_DIR` (в `_config.py`, вычисляется из `__file__`).
   - В конфиге — `side/config.json` относительными путями, `resolve_path()` раскрывает их от `BASE_DIR`.
   - Для внешних скриптов (тех, что лежат **вне** anyjson) — через env-var, например `ANYJSON_ETALONS_DIR`.
   - Никаких `r"E:\Jericho\..."` и `"C:/temp"` в коде. Только в докстрингах/примерах.
